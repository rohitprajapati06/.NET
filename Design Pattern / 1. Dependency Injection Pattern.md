## Dependency Injection (DI) Pattern in .NET

**Dependency Injection** is a design pattern used to provide an object with the dependencies it needs, instead of the object creating those dependencies itself.

### 1. Without Dependency Injection

Suppose we have an `OrderService` that needs `EmailService`.

```csharp
public class OrderService
{
    private EmailService _emailService;

    public OrderService()
    {
        _emailService = new EmailService();
    }

    public void PlaceOrder()
    {
        // Place order
        _emailService.SendEmail();
    }
}
```

Here, `OrderService` is **tightly coupled** to `EmailService`.

If we later want to replace `EmailService` with `SmsService`, we need to modify `OrderService`.

---

### 2. With Dependency Injection

We create an interface:

```csharp
public interface INotificationService
{
    void SendNotification();
}
```

Implement it:

```csharp
public class EmailService : INotificationService
{
    public void SendNotification()
    {
        Console.WriteLine("Email sent");
    }
}
```

Now inject it into `OrderService`:

```csharp
public class OrderService
{
    private readonly INotificationService _notificationService;

    public OrderService(INotificationService notificationService)
    {
        _notificationService = notificationService;
    }

    public void PlaceOrder()
    {
        // Place order
        _notificationService.SendNotification();
    }
}
```

Notice that `OrderService` **doesn't create** `EmailService`.

It simply says:

> "I need something that implements `INotificationService`."

This is **Dependency Injection**.

---

## 3. Register Dependency in ASP.NET Core

In `Program.cs`:

```csharp
builder.Services.AddScoped<INotificationService, EmailService>();
builder.Services.AddScoped<OrderService>();
```

ASP.NET Core's built-in **Dependency Injection container** will create and provide the required objects.

Then you can use it in a controller:

```csharp
public class OrderController : ControllerBase
{
    private readonly OrderService _orderService;

    public OrderController(OrderService orderService)
    {
        _orderService = orderService;
    }

    [HttpPost]
    public IActionResult PlaceOrder()
    {
        _orderService.PlaceOrder();

        return Ok();
    }
}
```

The dependency chain becomes:

```text
OrderController
       ↓
 OrderService
       ↓
INotificationService
       ↓
 EmailService
```

## Types of Dependency Injection

There are three common types:

### 1. Constructor Injection ⭐

Most commonly used in ASP.NET Core.

```csharp
public OrderService(INotificationService service)
{
    _service = service;
}
```

### 2. Property Injection

Dependency is provided through a property.

```csharp
public INotificationService NotificationService { get; set; }
```

Less commonly used.

### 3. Method Injection

Dependency is passed to a particular method.

```csharp
public void ProcessOrder(INotificationService service)
{
    service.SendNotification();
}
```

---

## Why do we use DI?

DI gives us:

* **Loose coupling**
* **Better unit testing**
* **Easy replacement of implementations**
* **Better maintainability**
* **Follows Dependency Inversion Principle**

For example, during unit testing we can provide a fake implementation:

```text
OrderService
     ↓
INotificationService
     ↓
FakeNotificationService
```

instead of actually sending an email.

---

### Interview answer

If an interviewer asks **"What is Dependency Injection?"**, you can say:

> **Dependency Injection is a design pattern where the dependencies required by a class are provided from outside rather than being created inside the class. In ASP.NET Core, the built-in DI container manages the creation and lifetime of these dependencies. This helps achieve loose coupling, maintainability, and easier unit testing.**
