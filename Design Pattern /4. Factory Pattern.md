## Factory Pattern in .NET Core Web API

The **Factory Pattern** is a creational design pattern used when we need to **create objects without exposing the object-creation logic to the calling code**.

In simple words:

> **Instead of directly creating an object using `new`, we ask a Factory to give us the required object.**

### Real-time example

Suppose your Web API supports different payment methods:

* Credit Card
* UPI
* PayPal

Without Factory Pattern:

```csharp
if (paymentType == "UPI")
{
    payment = new UpiPayment();
}
else if (paymentType == "Card")
{
    payment = new CardPayment();
}
else if (paymentType == "PayPal")
{
    payment = new PayPalPayment();
}
```

The controller now knows **how each object is created**. This can become difficult to maintain.

With Factory Pattern:

```text
Controller
    ↓
PaymentFactory
    ↓
 ┌───────────────┐
 │ UPI Payment   │
 │ Card Payment  │
 │ PayPal        │
 └───────────────┘
```

The controller simply asks:

```csharp
var payment = _paymentFactory.Create(paymentType);
payment.Pay();
```

---

# 1. Create an interface

```csharp
public interface IPayment
{
    void Pay(decimal amount);
}
```

---

# 2. Create implementations

### UPI

```csharp
public class UpiPayment : IPayment
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid ₹{amount} using UPI");
    }
}
```

### Credit Card

```csharp
public class CardPayment : IPayment
{
    public void Pay(decimal amount)
    {
        Console.WriteLine($"Paid ₹{amount} using Credit Card");
    }
}
```

---

# 3. Create the Factory

```csharp
public class PaymentFactory
{
    public IPayment Create(string paymentType)
    {
        return paymentType.ToLower() switch
        {
            "upi" => new UpiPayment(),
            "card" => new CardPayment(),
            _ => throw new ArgumentException("Invalid payment type")
        };
    }
}
```

The Factory is responsible for deciding **which implementation should be created**.

---

# 4. Use it in the Controller

```csharp
[ApiController]
[Route("api/[controller]")]
public class PaymentController : ControllerBase
{
    private readonly PaymentFactory _paymentFactory;

    public PaymentController(PaymentFactory paymentFactory)
    {
        _paymentFactory = paymentFactory;
    }

    [HttpPost]
    public IActionResult Pay(string paymentType, decimal amount)
    {
        var payment = _paymentFactory.Create(paymentType);

        payment.Pay(amount);

        return Ok("Payment successful");
    }
}
```

---

# 5. Register Factory with DI

In `Program.cs`:

```csharp
builder.Services.AddScoped<PaymentFactory>();
```

Now ASP.NET Core Dependency Injection will provide the Factory to the controller.

---

## Why use Factory Pattern?

### Without Factory

The controller contains:

```csharp
new UpiPayment()
new CardPayment()
new PayPalPayment()
```

So the controller is tightly coupled to concrete classes.

### With Factory

The controller only knows:

```csharp
_paymentFactory.Create(paymentType);
```

This gives you:

* **Loose coupling**
* Centralized object creation
* Easier maintenance
* Easier addition of new implementations
* Cleaner controllers

## Interview Example

If the interviewer asks:

**"What is Factory Pattern and where have you used it?"**

You can answer:

> "Factory Pattern is a creational design pattern used to centralize object creation. Instead of the controller directly creating different implementations using `new`, we use a Factory that decides which implementation to create based on some input. For example, in a payment API, the Factory can return UPI, Credit Card, or PayPal payment implementations. This reduces coupling between the controller and concrete classes and makes the application easier to maintain and extend."

### One important point

In **ASP.NET Core**, Factory Pattern is often combined with **Dependency Injection**. The Factory decides **which implementation to use**, while DI manages **the lifetime and dependencies of those objects**.

**Easy way to remember:**

> **Factory = "Which object should I create?"**
> **Dependency Injection = "How should I provide/manage that object?"**
