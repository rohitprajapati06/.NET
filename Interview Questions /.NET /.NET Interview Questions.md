
# .NET Core Interview Questions

### 1. What is Dependency Injection in .NET?

**Answer:**
Dependency Injection (DI) is a design pattern where required dependencies are provided to a class instead of the class creating them itself.

```csharp
public class OrderService
{
    private readonly IOrderRepository _repository;

    public OrderService(IOrderRepository repository)
    {
        _repository = repository;
    }
}
```

ASP.NET Core has a **built-in DI container**.

**Benefits:** loose coupling, easier testing, maintainability.

### 2. What are the different Service Lifetimes?

There are three:

| Lifetime      | Instance                            | Common Usage                   |
| ------------- | ----------------------------------- | ------------------------------ |
| **Transient** | New instance every time             | Lightweight/stateless services |
| **Scoped**    | One instance per HTTP request       | `DbContext`, business services |
| **Singleton** | One instance for entire application | Caching/configuration services |

**Bad choices:**

* Singleton for request-specific/stateful data → concurrency issues.
* Scoped dependency inside Singleton → lifetime violation.
* Transient for expensive/stateful services → unnecessary object creation.

---

### 3. Why is `DbContext` usually Scoped?

`DbContext` represents a **unit of work for a request**.

A Scoped lifetime ensures:

```text
HTTP Request
    ↓
One DbContext
    ↓
Multiple database operations
    ↓
SaveChanges()
    ↓
Request ends → DbContext disposed
```

It also allows EF Core to maintain **change tracking within that request**.

---

### 4. What happens if a Singleton depends on a Scoped service?

This creates a **lifetime mismatch**.

Example:

```csharp
SingletonService
       ↓
   ScopedService
```

The Singleton lives for the application's lifetime, while the Scoped service is supposed to live only for one request.

ASP.NET Core generally detects this during development and throws an exception such as:

> Cannot consume scoped service from singleton.

**Solution:** Don't directly inject the scoped service into the singleton. If appropriate, use `IServiceScopeFactory` to create a scope.

### 5. What is Middleware in ASP.NET Core?

Middleware is a component in the HTTP request pipeline that can:

* Process incoming requests
* Perform operations before/after the next middleware
* Modify the request/response
* Short-circuit the pipeline

Example:

```csharp
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
```

Custom middleware:

```csharp
public async Task InvokeAsync(HttpContext context)
{
    // Before
    await _next(context);
    // After
}
```

---

### 6. What happens when an HTTP request enters ASP.NET Core?

The request passes through the **ASP.NET Core middleware pipeline**.

Simplified flow:

```text
Client
  ↓
Kestrel
  ↓
Middleware Pipeline
  ↓
Routing
  ↓
Authentication
  ↓
Authorization
  ↓
Controller / Endpoint
  ↓
Action
  ↓
Response
```

Each middleware can process the request and either:

1. Call the next middleware, or
2. Stop the pipeline and return a response.

---

### 7. Why does Middleware order matter?

Middleware executes **in the order it is registered**.

For example:

```csharp
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
```

Authentication must happen before authorization because authorization needs to know **who the user is**.

Incorrect ordering can cause authentication, authorization, exception handling, CORS, or routing to behave incorrectly.

### 8. What is Global Exception Handling?

Instead of handling exceptions separately in every controller, we handle them centrally.

Common approaches:

* Exception-handling middleware
* `UseExceptionHandler()`
* Custom exception middleware
* `IExceptionHandler`

Example concept:

```text
Controller
    ↓
Exception
    ↓
Global Exception Handler
    ↓
Log exception
    ↓
Return appropriate HTTP response
```

This provides **consistent error responses and centralized logging**.

### 9. What is the difference between Authentication and Authorization?

**Authentication** → Who are you?

**Authorization** → What are you allowed to do?

Example:

```text
Login
 ↓
Authentication → User identified
 ↓
Authorization → Does user have Admin permission?
 ↓
Allow/Deny
```

In ASP.NET Core:

```csharp
[Authorize]
public IActionResult GetData()
{
    ...
}
```

### 10. How does JWT Authentication work?

Typical flow:

```text
Client → Login
          ↓
      API validates credentials
          ↓
      JWT generated
          ↓
Client receives JWT
          ↓
Client sends JWT with requests
          ↓
Authorization middleware validates token
          ↓
Controller executes
```

The token is normally sent as:

```http
Authorization: Bearer <token>
```

JWT commonly contains claims such as user ID, role, and expiration.

### 11. What is CORS?

**CORS (Cross-Origin Resource Sharing)** controls whether a browser-based client from one origin can access an API from another origin.

Example:

```text
Angular:  https://frontend.com
API:      https://api.example.com
```

These are different origins.

ASP.NET Core configuration:

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
    {
        policy.WithOrigins("https://frontend.com")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});
```

Then:

```csharp
app.UseCors("AllowFrontend");
```

### 14. Why can `return Ok(user)` be dangerous?

Because it may expose **sensitive/internal properties** of the domain entity.

For example:

```csharp
return Ok(user);
```

might accidentally expose:

```text
PasswordHash
InternalId
Security information
Audit fields
Internal database properties
```

Better approach: return a **DTO**.

```csharp
return Ok(new UserDto
{
    Id = user.Id,
    Name = user.Name,
    Email = user.Email
});
```

### 15. What is the difference between `IEnumerable`, `IQueryable`, and `IAsyncEnumerable`?

| Type                  | Execution               | Typical Usage           |
| --------------------- | ----------------------- | ----------------------- |
| `IEnumerable<T>`      | In-memory               | Collections             |
| `IQueryable<T>`       | Query provider/database | EF Core queries         |
| `IAsyncEnumerable<T>` | Asynchronous streaming  | Large async result sets |

Example:

```csharp
IQueryable<User> users = context.Users;

var result = await users
    .Where(x => x.IsActive)
    .ToListAsync();
```

The filtering can be translated into SQL and executed by the database.

### 16. What is the difference between `First`, `Single`, and their `OrDefault` versions?

| Method              | No match     | Multiple matches |
| ------------------- | ------------ | ---------------- |
| `First()`           | Exception    | Returns first    |
| `FirstOrDefault()`  | Default/null | Returns first    |
| `Single()`          | Exception    | Exception        |
| `SingleOrDefault()` | Default/null | Exception        |

Use:

* `First()` → you only need the first item and expect one to exist.
* `FirstOrDefault()` → first item may not exist.
* `Single()` → exactly one record is expected.
* `SingleOrDefault()` → zero or one record is expected.

### 17. Explain `async` and `await` in .NET.

`async` allows a method to perform asynchronous operations.

`await` waits for an asynchronous operation **without blocking the calling thread**.

```csharp
public async Task<User> GetUserAsync(int id)
{
    return await repository.GetUserAsync(id);
}
```

This is particularly useful in Web APIs for **I/O-bound operations** such as database calls, HTTP calls, and file operations.

---

### 18. What is the difference between `Task`, `Thread`, and `async/await`?

**Thread** → actual execution thread managed by the OS/runtime.

**Task** → represents an asynchronous operation.

**async/await** → language features used to write asynchronous code conveniently.

Simplified:

```text
Thread
  ↓
Executes work

Task
  ↓
Represents work

async/await
  ↓
Makes asynchronous Task-based code easier to write
```

---

### 19. Why is `async Task` preferred over `async void`?

Prefer:

```csharp
public async Task ProcessAsync()
{
    await ...
}
```

instead of:

```csharp
public async void ProcessAsync()
{
    await ...
}
```

`Task` allows the caller to:

* Await the operation
* Handle exceptions
* Compose multiple async operations
* Know when the operation completes

`async void` is mainly appropriate for **event handlers**.

### 20. What is the Repository Pattern?

Repository Pattern abstracts data-access operations from business logic.

```text
Controller
    ↓
Service
    ↓
Repository
    ↓
EF Core
    ↓
Database
```

Example:

```csharp
public interface IUserRepository
{
    Task<User?> GetByIdAsync(int id);
}
```

It can improve separation of concerns and testability, although EF Core's `DbContext` already provides repository/unit-of-work-like functionality, so an additional repository layer isn't always necessary.

---

### 21. What is the Unit of Work Pattern?

Unit of Work groups multiple database operations into a **single transaction/work unit**.

Example:

```text
Create Order
    +
Update Inventory
    +
Create Payment Record
        ↓
    Save/Commit
```

If an operation fails, the transaction can be rolled back.

In EF Core, `DbContext` already behaves similarly to a Unit of Work because it tracks changes and persists them through `SaveChanges()`.

### 22. What happens internally when `SaveChanges()` is called?

Simplified EF Core flow:

```text
Entity changes
      ↓
Change Tracker detects changes
      ↓
EF Core generates SQL
      ↓
Database executes SQL
      ↓
Transaction/commit
      ↓
Entity state updated
```

For example:

```csharp
user.Name = "Rohit";

await context.SaveChangesAsync();
```

EF Core detects the modified entity and generates the appropriate `UPDATE`.

---

### 23. What is Change Tracking in EF Core?

Change Tracking allows EF Core to monitor entities retrieved through a tracking query.

Example:

```csharp
var user = await context.Users.FindAsync(id);

user.Name = "New Name";

await context.SaveChangesAsync();
```

EF Core knows that `Name` changed and generates an `UPDATE`.

---

### 24. When should you use `AsNoTracking()`?

Use it when entities are **only being read** and don't need to be updated through the same `DbContext`.

```csharp
var users = await context.Users
    .AsNoTracking()
    .ToListAsync();
```

Benefits:

* Less memory usage
* Less change-tracking overhead
* Can improve read-only query performance

Good for **read-only APIs/reporting queries**.

### 25. What are Lazy Loading, Eager Loading and Explicit Loading?

**Eager Loading**

Load related data immediately:

```csharp
context.Orders
    .Include(x => x.Customer);
```

**Lazy Loading**

Related data is loaded automatically when accessed.

**Explicit Loading**

You explicitly request the related data:

```csharp
await context.Entry(order)
    .Reference(x => x.Customer)
    .LoadAsync();
```

### 26. What is the N+1 Query Problem in EF Core?

It occurs when one query retrieves the main records and then **one additional query is executed for each record**.

Example:

```text
1 query → Get 100 orders
100 queries → Get customer/details for each order

Total = 101 queries
```

This can severely hurt performance.

Common solutions:

* `Include()`
* Projection using `Select()`
* Properly designed queries

Example:

```csharp
var orders = await context.Orders
    .Include(x => x.Customer)
    .ToListAsync();
```

---

### 27. Why can too many `Include()` calls hurt performance?

Multiple `Include()` calls can generate large and complex SQL queries, potentially producing:

* Large joins
* Duplicate result rows
* More data transferred
* Higher database load

Instead of loading an entire object graph, often use **projection**:

```csharp
var result = await context.Orders
    .Select(x => new OrderDto
    {
        Id = x.Id,
        CustomerName = x.Customer.Name
    })
    .ToListAsync();
```

Only required data is retrieved.

### 28. What is EF Core?

**Entity Framework Core** is Microsoft's ORM for .NET.

It allows developers to work with databases using C# objects and LINQ rather than writing SQL for every operation.

Important components:

* `DbContext`
* `DbSet`
* Change Tracking
* LINQ
* Migrations
* Transactions
* Concurrency handling

### 29. What are Migrations in EF Core?

Migrations allow you to keep the **database schema synchronized with changes to your entity model**.

Typical flow:

```text
Change Entity
    ↓
Create Migration
    ↓
Migration contains schema changes
    ↓
Apply Migration
    ↓
Database updated
```

Example:

```bash
dotnet ef migrations add AddPhoneNumber
dotnet ef database update
```

### 30. How do you handle optimistic concurrency in .NET + EF Core?

Optimistic concurrency assumes conflicts are relatively uncommon.

A common SQL Server approach is a **row version/concurrency token**.

Conceptually:

```text
User A reads Record → Version 5
User B reads Record → Version 5

User A updates → Version becomes 6

User B tries update using Version 5
       ↓
No matching version
       ↓
Concurrency conflict
```

EF Core can detect this and throw `DbUpdateConcurrencyException`.

The application can then inform the user that the record was modified by someone else and require a refresh/retry.

### 31. How would you troubleshoot a slow .NET Web API in production?

I would investigate systematically:

```text
API
 ↓
Application logs
 ↓
Application performance/metrics
 ↓
CPU / Memory
 ↓
Database queries
 ↓
External API calls
 ↓
Network
 ↓
Caching
```

Check:

* Request latency
* CPU and memory
* Slow database queries
* N+1 queries
* Thread pool/async issues
* External service latency
* Logs and exceptions
* Cache performance

The goal is to identify the **actual bottleneck before optimizing**.

### 32. How would you handle high-volume concurrent requests?

Key approaches include:

* Use asynchronous I/O
* Optimize database queries
* Connection pooling
* Caching where appropriate
* Avoid blocking calls
* Control concurrency where required
* Horizontal scaling
* Queue background work
* Monitor CPU, memory, latency and throughput

For expensive operations:

```text
HTTP Request
     ↓
Queue
     ↓
Background Worker
     ↓
Process asynchronously
```

This prevents long-running work from unnecessarily blocking API requests.

### 33. How would you implement API versioning?

The goal is to introduce changes without breaking existing consumers.

For example:

```text
/api/v1/orders
/api/v2/orders
```

Existing clients continue using v1 while newer clients migrate to v2.

Other strategies include header- or query-based versioning, depending on the API design.

### 34. How would you implement idempotency in a payment API?

If a user clicks **Pay twice**, the API should not create two transactions.

Use an **idempotency key**:

```text
Request 1
Idempotency-Key: ABC123
        ↓
Process payment
        ↓
Store result for ABC123

Request 2
Idempotency-Key: ABC123
        ↓
Detect existing request
        ↓
Return previous result
```

The key should be persisted in a durable store with appropriate uniqueness/concurrency controls.

---

### 35. How would you handle a background job processing the same message multiple times?

Design the consumer to be **idempotent**.

For example:

```text
Message ID = 123

Check:
Has message 123 already been processed?

YES → Ignore/return
NO  → Process → Mark as processed
```

A durable processed-message record or equivalent idempotency mechanism can prevent duplicate business effects.
