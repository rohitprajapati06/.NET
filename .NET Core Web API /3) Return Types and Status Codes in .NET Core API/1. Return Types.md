# ASP.NET Core Web API – Action Return Types and Status Codes

For interviews and real-world ASP.NET Core Web API development, you should understand **what an action returns** and **which HTTP status code should be returned**.

---

## 1. What is an Action Return Type?

An **action** is a method inside a controller that handles an HTTP request.

Example:

```csharp
[HttpGet]
public IActionResult GetPatients()
{
    return Ok();
}
```

The return type tells ASP.NET Core **what kind of HTTP response the action produces**.

The most common return types are:

1. `IActionResult`
2. `ActionResult<T>`
3. Specific type (`PatientResponse`, `List<PatientResponse>`, etc.)
4. `HttpResults` / `IResult` — more commonly associated with Minimal APIs

For a typical Controller-based Web API, focus mainly on **`IActionResult` and `ActionResult<T>`**.

---

# 2. `IActionResult`

`IActionResult` represents an HTTP response.

```csharp
[HttpGet]
public IActionResult GetPatient()
{
    return Ok();
}
```

You can return different responses from the same action:

```csharp
[HttpGet("{id}")]
public IActionResult GetPatient(int id)
{
    var patient = GetPatientFromDatabase(id);

    if (patient == null)
        return NotFound();

    return Ok(patient);
}
```

Possible responses:

* `200 OK` → patient found
* `404 Not Found` → patient doesn't exist

### Common `IActionResult` methods

```csharp
return Ok(data);
return Created(...);
return NoContent();
return BadRequest();
return Unauthorized();
return Forbid();
return NotFound();
return Conflict();
```

### Why use `IActionResult`?

Because an API action can return **different HTTP responses**.

```csharp
public IActionResult GetPatient(int id)
```

could return:

```text
200 OK
404 Not Found
400 Bad Request
```

---

# 3. `ActionResult<T>`

This is often the **preferred choice for controller APIs** when the successful response has a known type.

Example:

```csharp
[HttpGet("{id}")]
public ActionResult<PatientResponse> GetPatient(int id)
{
    var patient = GetPatientFromDatabase(id);

    if (patient == null)
        return NotFound();

    return Ok(patient);
}
```

Here:

```csharp
ActionResult<PatientResponse>
```

means:

> The successful response contains a `PatientResponse`, but the action can also return an HTTP error response.

For example:

```text
200 OK → PatientResponse
404 Not Found
```

---

# 4. `IActionResult` vs `ActionResult<T>`

This is an important interview question.

| `IActionResult`                    | `ActionResult<T>`                             |
| ---------------------------------- | --------------------------------------------- |
| Represents any HTTP response       | Represents HTTP response + expected data type |
| Doesn't specify response body type | Specifies successful response body type       |
| Good when response types vary      | Good when success response has a known type   |
| Less type-safe                     | More type-safe                                |
| Common in older ASP.NET Core code  | Generally preferred for typed controller APIs |

### Example

```csharp
public IActionResult GetPatient(int id)
```

vs.

```csharp
public ActionResult<PatientResponse> GetPatient(int id)
```

The second one communicates more information:

> "This endpoint normally returns `PatientResponse`, but it can also return an error."

---

# 5. Returning a Specific Type

You can also directly return a model:

```csharp
[HttpGet("{id}")]
public PatientResponse GetPatient(int id)
{
    return new PatientResponse
    {
        Id = id,
        Name = "John"
    };
}
```

This is simple, but it becomes inconvenient when you need different HTTP responses.

For example, what if the patient doesn't exist?

You can't naturally do:

```csharp
return NotFound();
```

because the method expects:

```csharp
PatientResponse
```

Therefore:

```csharp
ActionResult<PatientResponse>
```

is generally more practical for controller APIs.

---

# 6. `ActionResult<T>` with Direct Return

You don't always need `Ok()`.

This:

```csharp
public ActionResult<PatientResponse> GetPatient()
{
    return Ok(patient);
}
```

can often be written as:

```csharp
public ActionResult<PatientResponse> GetPatient()
{
    return patient;
}
```

ASP.NET Core interprets the returned object as a successful response.

However, many teams prefer:

```csharp
return Ok(patient);
```

because it makes the intended HTTP response explicit.
