# HTTP Status Codes in ASP.NET Core Web API

---

# 1. Most Important Status Codes

For your .NET Core interview preparation, I'd memorize this table:

|  Status | Name                  | When to use                                   |
| ------: | --------------------- | --------------------------------------------- |
| **200** | OK                    | Successful request                            |
| **201** | Created               | Resource successfully created                 |
| **204** | No Content            | Successful operation with no response body    |
| **400** | Bad Request           | Invalid request                               |
| **401** | Unauthorized          | Authentication required/failed                |
| **403** | Forbidden             | Authenticated but insufficient permission     |
| **404** | Not Found             | Resource doesn't exist                        |
| **409** | Conflict              | Request conflicts with current resource state |
| **500** | Internal Server Error | Unexpected server-side error                  |
| **503** | Service Unavailable   | Service temporarily unavailable               |

---


# 2. `200 OK`

The request was successful.

### GET

```csharp
[HttpGet("{id}")]
public IActionResult GetPatient(int id)
{
    var patient = GetPatient(id);

    return Ok(patient);
}
```

Response:

```text
200 OK
```

Usually used for:

* Successful GET
* Successful PUT when returning data
* Successful operation where a response body is returned

---

# 3. `201 Created`

A **new resource was successfully created**.

Most commonly used with `POST`.

```csharp
[HttpPost]
public IActionResult CreatePatient(CreatePatientRequest request)
{
    var patient = CreatePatient(request);

    return CreatedAtAction(
        nameof(GetPatient),
        new { id = patient.Id },
        patient);
}
```

Response:

```text
201 Created
```

### Interview point

Don't use `200 OK` for resource creation when `201 Created` is appropriate.

---

# 4. `204 No Content`

The operation was successful, but there is **nothing to return in the response body**.

```csharp
return NoContent();
```

Commonly used for:

```text
PUT → 204
DELETE → 204
```

Example:

```csharp
[HttpDelete("{id}")]
public IActionResult DeletePatient(int id)
{
    DeletePatient(id);

    return NoContent();
}
```

Response:

```text
204 No Content
```

---

# 5. `400 Bad Request`

The request sent by the client is invalid.

```csharp
if (id <= 0)
{
    return BadRequest("Invalid patient ID.");
}
```

Response:

```text
400 Bad Request
```

Examples:

* Invalid input
* Invalid request format
* Validation failure
* Invalid parameters

With `[ApiController]`, ASP.NET Core can automatically return `400` when model validation fails.

---

# 6. `401 Unauthorized`

The client is **not authenticated**.

For example:

```text
Client
  ↓
API
  ↓
No valid authentication
  ↓
401 Unauthorized
```

Typical situation:

```text
Authorization header missing
```

or invalid authentication credentials.

### Easy way to remember

> **401 = You are not authenticated.**

---

# 7. `403 Forbidden`

The client is authenticated, but **doesn't have permission** to access the resource.

Example:

```text
User is logged in
        ↓
User tries to access Admin API
        ↓
User isn't Admin
        ↓
403 Forbidden
```

### Difference between 401 and 403

```text
401 → Who are you?
403 → I know who you are, but you can't do this.
```

This is a very common interview question.

---

# 8. `404 Not Found`

The requested resource doesn't exist.

```csharp
var patient = await context.Patients
    .FirstOrDefaultAsync(x => x.Id == id);

if (patient == null)
{
    return NotFound();
}

return Ok(patient);
```

Response:

```text
404 Not Found
```

Example:

```http
GET /api/patients/100
```

If patient `100` doesn't exist:

```text
404
```

---

# 9. `409 Conflict`

The request conflicts with the current state of the resource.

Example:

```csharp
if (existingPatient != null)
{
    return Conflict("Patient already exists.");
}
```

Response:

```text
409 Conflict
```

Common examples:

* Duplicate resource
* Duplicate unique email
* State conflict
* Concurrency-related conflicts

---

# 10. `500 Internal Server Error`

Something unexpected went wrong on the server.

For example:

```text
Controller
   ↓
Service
   ↓
Database
   ↓
Exception
   ↓
500 Internal Server Error
```

In a properly structured ASP.NET Core application, you generally **don't put `try/catch` in every controller just to return 500**.

Instead, use centralized exception handling/middleware.

---

# 11. `503 Service Unavailable`

The server is temporarily unable to handle the request.

Typical examples:

* Database unavailable
* Dependent service unavailable
* Server overloaded
* Temporary maintenance

```text
503 Service Unavailable
```

You don't need to use this frequently in normal controller code, but know what it means.



# 12. HTTP Method + Status Code

This is probably the **most useful thing to remember**:

```text
GET
 ├── Found       → 200 OK
 └── Not Found   → 404

POST
 ├── Created     → 201 Created
 ├── Invalid     → 400
 └── Conflict    → 409

PUT
 ├── Updated     → 200 OK / 204 No Content
 ├── Not Found   → 404
 └── Invalid     → 400

DELETE
 ├── Deleted     → 204 No Content
 └── Not Found   → 404
```
