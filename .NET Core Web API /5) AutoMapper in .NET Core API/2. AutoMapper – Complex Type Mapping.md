# AutoMapper – Complex Type Mapping

**Complex Type Mapping** means mapping an object that contains another object as a property.

For example, a `Patient` may have an `Address` object.

```text
Patient
 ├── Id
 ├── Name
 └── Address
      ├── City
      └── State
```

AutoMapper can map these nested objects automatically **if a mapping exists for the nested types**.

---

## 1. Example Classes

### Entity

```csharp
public class Patient
{
    public int Id { get; set; }
    public string Name { get; set; }

    public Address Address { get; set; }
}

public class Address
{
    public string City { get; set; }
    public string State { get; set; }
}
```

### DTO

```csharp
public class PatientDto
{
    public int Id { get; set; }
    public string Name { get; set; }

    public AddressDto Address { get; set; }
}

public class AddressDto
{
    public string City { get; set; }
    public string State { get; set; }
}
```

---

## 2. Configure the Mapping

You need mappings for **both** the parent and nested objects:

```csharp
public class MappingProfile : Profile
{
    public MappingProfile()
    {
        CreateMap<Patient, PatientDto>();
        CreateMap<Address, AddressDto>();
    }
}
```

Then:

```csharp
var patientDto = _mapper.Map<PatientDto>(patient);
```

AutoMapper will perform:

```text
Patient
   │
   ├── Id ──────────> Id
   ├── Name ────────> Name
   │
   └── Address
          │
          ├── City ──> City
          └── State ─> State
```

---

# 3. Why is the Address Mapping Required?

This is important.

If you only have:

```csharp
CreateMap<Patient, PatientDto>();
```

AutoMapper knows how to map:

```text
Patient → PatientDto
```

But it may not know how to convert:

```text
Address → AddressDto
```

So define:

```csharp
CreateMap<Address, AddressDto>();
```

AutoMapper can then use that mapping while mapping the parent object.

---

# 4. Different Property Names

Suppose your entity has:

```csharp
public class Patient
{
    public int Id { get; set; }
    public Address PatientAddress { get; set; }
}
```

But your DTO has:

```csharp
public class PatientDto
{
    public int Id { get; set; }
    public AddressDto Address { get; set; }
}
```

Now the property names don't match.

Configure it:

```csharp
CreateMap<Patient, PatientDto>()
    .ForMember(
        dest => dest.Address,
        opt => opt.MapFrom(src => src.PatientAddress)
    );

CreateMap<Address, AddressDto>();
```

Now:

```text
Patient.PatientAddress
          ↓
     Address mapping
          ↓
PatientDto.Address
```

---

# 5. Nested Complex Types

Complex types can also be nested multiple levels deep.

```csharp
public class Patient
{
    public int Id { get; set; }
    public NameInfo Name { get; set; }
}

public class NameInfo
{
    public string FirstName { get; set; }
    public string LastName { get; set; }
}
```

DTO:

```csharp
public class PatientDto
{
    public int Id { get; set; }
    public NameInfoDto Name { get; set; }
}

public class NameInfoDto
{
    public string FirstName { get; set; }
    public string LastName { get; set; }
}
```

Mappings:

```csharp
CreateMap<Patient, PatientDto>();
CreateMap<NameInfo, NameInfoDto>();
```

AutoMapper handles the nested mapping.

---

# 6. Real-World Example

Consider a healthcare application:

```csharp
public class Appointment
{
    public int Id { get; set; }
    public Patient Patient { get; set; }
    public Doctor Doctor { get; set; }
}
```

DTO:

```csharp
public class AppointmentDto
{
    public int Id { get; set; }
    public PatientDto Patient { get; set; }
    public DoctorDto Doctor { get; set; }
}
```

Mapping:

```csharp
public class MappingProfile : Profile
{
    public MappingProfile()
    {
        CreateMap<Appointment, AppointmentDto>();

        CreateMap<Patient, PatientDto>();

        CreateMap<Doctor, DoctorDto>();
    }
}
```

Then simply:

```csharp
var result = _mapper.Map<AppointmentDto>(appointment);
```

AutoMapper maps the entire object graph:

```text
Appointment
│
├── Id
│
├── Patient
│     ├── Id
│     ├── Name
│     └── Email
│
└── Doctor
      ├── Id
      ├── Name
      └── Specialization
```

into:

```text
AppointmentDto
│
├── Id
│
├── PatientDto
│
└── DoctorDto
```

---

## 7. Important Point: Navigation Properties

This becomes especially important with **Entity Framework Core**.

Suppose:

```csharp
Appointment
    ├── Patient
    └── Doctor
```

AutoMapper can map them **only if the related objects are actually available**.

For example:

```csharp
var appointment = await context.Appointments
    .Include(x => x.Patient)
    .Include(x => x.Doctor)
    .FirstAsync(x => x.Id == id);
```

Then:

```csharp
var dto = _mapper.Map<AppointmentDto>(appointment);
```

Without loading the navigation properties, `Patient` or `Doctor` may be `null` depending on your EF Core configuration.

---

## Interview Summary

Remember these three things:

| Concept                  | Example                            |
| ------------------------ | ---------------------------------- |
| Simple mapping           | `CreateMap<Patient, PatientDto>()` |
| Complex/Nested mapping   | `CreateMap<Address, AddressDto>()` |
| Different property names | `.ForMember(...MapFrom(...))`      |

The most important rule is:

> **For nested/complex objects, AutoMapper needs to know how to map the nested source type to the nested destination type.**

So:

```csharp
CreateMap<Appointment, AppointmentDto>();
CreateMap<Patient, PatientDto>();
CreateMap<Doctor, DoctorDto>();
```

allows one call:

```csharp
_mapper.Map<AppointmentDto>(appointment);
```

to map the complete nested object structure.
