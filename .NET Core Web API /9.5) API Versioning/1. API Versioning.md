# ASP.NET Core Web API Versioning

**API Versioning** allows you to maintain multiple versions of an API so that you can introduce breaking changes without breaking existing clients.

### Why do we need API Versioning?

Suppose your existing API returns:

```http
GET /api/products/10
```

Response:

```json
{
  "id": 10,
  "name": "Laptop"
}
```

Later, you want to change the response:

```json
{
  "productId": 10,
  "productName": "Laptop",
  "price": 50000
}
```

Existing clients may depend on the old structure. Instead of changing the existing API, create **v2**.

```text
v1 → Existing clients
v2 → New clients
```

---

## 1. Install API Versioning Package

For current ASP.NET Core applications, the commonly used package is:

```bash
dotnet add package Asp.Versioning.Mvc
```

For Swagger support:

```bash
dotnet add package Asp.Versioning.Mvc.ApiExplorer
```

---

## 2. Configure Versioning

In `Program.cs`:

```csharp
using Asp.Versioning;

builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);

    options.AssumeDefaultVersionWhenUnspecified = true;

    options.ReportApiVersions = true;
});
```

### Important options

| Option                                | Purpose                                                |
| ------------------------------------- | ------------------------------------------------------ |
| `DefaultApiVersion`                   | Default API version                                    |
| `AssumeDefaultVersionWhenUnspecified` | Uses default version if client doesn't specify one     |
| `ReportApiVersions`                   | Adds supported/deprecated versions to response headers |

---

# 3. URL Path Versioning

This is one of the easiest approaches to understand.

### Controller

```csharp
[ApiController]
[Route("api/v{version:apiVersion}/products")]
[ApiVersion(1.0)]
public class ProductsV1Controller : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        return Ok(new
        {
            Id = 1,
            Name = "Laptop"
        });
    }
}
```

Call:

```http
GET /api/v1/products
```

Response:

```json
{
  "id": 1,
  "name": "Laptop"
}
```

---

## 4. Create V2

```csharp
[ApiController]
[Route("api/v{version:apiVersion}/products")]
[ApiVersion(2.0)]
public class ProductsV2Controller : ControllerBase
{
    [HttpGet]
    public IActionResult Get()
    {
        return Ok(new
        {
            ProductId = 1,
            ProductName = "Laptop",
            Price = 50000
        });
    }
}
```

Now:

```http
GET /api/v1/products
```

returns the V1 structure, while:

```http
GET /api/v2/products
```

returns the V2 structure.

---

# 5. Query String Versioning

Instead of putting the version in the URL:

```http
GET /api/products?api-version=1.0
```

Configure:

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);
    options.AssumeDefaultVersionWhenUnspecified = true;
    
    options.ApiVersionReader =
        new QueryStringApiVersionReader("api-version");
});
```

Now clients specify:

```http
/api/products?api-version=1.0
```

or:

```http
/api/products?api-version=2.0
```

---

# 6. Header Versioning

Version can also be sent through a request header.

```http
GET /api/products
api-version: 2.0
```

Configuration:

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.DefaultApiVersion = new ApiVersion(1, 0);

    options.ApiVersionReader =
        new HeaderApiVersionReader("api-version");
});
```

---

# 7. Combining Versioning Strategies

You can support multiple methods:

```csharp
options.ApiVersionReader =
    ApiVersionReader.Combine(
        new UrlSegmentApiVersionReader(),
        new QueryStringApiVersionReader("api-version"),
        new HeaderApiVersionReader("api-version")
    );
```

Then clients could use:

```http
/api/v1/products
```

or:

```http
/api/products?api-version=1.0
```

or:

```http
GET /api/products
api-version: 1.0
```

---

# 8. Deprecating an API Version

Suppose V1 should no longer be used:

```csharp
[ApiVersion(1.0, Deprecated = true)]
[ApiVersion(2.0)]
```

With:

```csharp
options.ReportApiVersions = true;
```

the API can communicate version information to clients through response headers.

# Real-World Example

Imagine your **Healthcare API** has:

```text
/api/v1/doctors
/api/v1/appointments
/api/v1/patients
```

You later change the Doctor response.

### V1

```json
{
  "id": 1,
  "name": "Dr. Sharma"
}
```

### V2

```json
{
  "doctorId": 1,
  "firstName": "Raj",
  "lastName": "Sharma",
  "specialization": "Cardiology",
  "hospital": "ABC Hospital"
}
```

You can keep:

```http
GET /api/v1/doctors
```

for existing applications and introduce:

```http
GET /api/v2/doctors
```

for new applications.

### Interview Definition

> **API Versioning is a technique used to maintain different versions of an API simultaneously, allowing us to introduce breaking changes while keeping existing clients working with the older version.**

For a .NET interview, know **URL, Query String, and Header versioning**, with **URL versioning** being the easiest to demonstrate.
