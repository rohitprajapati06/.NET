# Model Binding using `[FromForm]` in ASP.NET Core Web API

`[FromForm]` tells ASP.NET Core:

> **"Get this parameter/property from the HTTP form data submitted by the client."**

It is mainly used when the request has:

```http
Content-Type: multipart/form-data
```

or, for simple form fields, `application/x-www-form-urlencoded`.

The most important real-world use case is **file upload + other form fields**.

---

## 1. Basic Example

Suppose we have:

```csharp
public class CreateHospitalRequest
{
    public string Name { get; set; }

    public string City { get; set; }

    public string State { get; set; }
}
```

Controller:

```csharp
[HttpPost]
public IActionResult CreateHospital(
    [FromForm] CreateHospitalRequest request)
{
    return Ok(request);
}
```

Client sends:

```text
POST /api/hospitals
Content-Type: multipart/form-data
```

Form data:

| Key   | Value           |
| ----- | --------------- |
| Name  | Apollo Hospital |
| City  | Mumbai          |
| State | Maharashtra     |

ASP.NET Core performs:

```text
Form Data
    ↓
Model Binding
    ↓
CreateHospitalRequest
    ↓
Controller
```

So:

```csharp
request.Name
// Apollo Hospital

request.City
// Mumbai

request.State
// Maharashtra
```

# 2. `[FromForm]` with File Upload

This is where `[FromForm]` becomes particularly important.

Suppose you're implementing your **hospital Excel import** functionality.

You might have:

```csharp
[HttpPost("import")]
public async Task<IActionResult> ImportHospitals(
    [FromForm] IFormFile file)
{
    if (file == null || file.Length == 0)
    {
        return BadRequest("File is required.");
    }

    // Process Excel file

    return Ok();
}
```

The request from Postman would be:

```text
POST /api/hospitals/import
```

Body:

```text
form-data

Key       Type
--------------------
file      File
```

The model binder takes the uploaded file and gives you:

```csharp
IFormFile file
```

# 3. `[FromForm]` with File + Other Properties

This is a very common enterprise pattern.

For example:

```csharp
public class HospitalImportRequest
{
    public IFormFile File { get; set; }

    public string HospitalType { get; set; }

    public int CreatedBy { get; set; }
}
```

Controller:

```csharp
[HttpPost("import")]
public async Task<IActionResult> ImportHospitals(
    [FromForm] HospitalImportRequest request)
{
    var file = request.File;
    var hospitalType = request.HospitalType;
    var createdBy = request.CreatedBy;

    // Import logic

    return Ok();
}
```

Postman:

```text
Body → form-data
```

| Key          | Type | Value          |
| ------------ | ---- | -------------- |
| File         | File | hospitals.xlsx |
| HospitalType | Text | Government     |
| CreatedBy    | Text | 101            |

ASP.NET Core binds them into:

```csharp
HospitalImportRequest
{
    File = uploaded file,
    HospitalType = "Government",
    CreatedBy = 101
}
```

# 4. Why not `[FromBody]`?

This is an important distinction.

You **cannot normally send a file as JSON** like this:

```json
{
    "file": "hospitals.xlsx"
}
```

A file contains binary data.

Instead, use:

```text
multipart/form-data
```

and:

```csharp
[FromForm]
```

So:

| `[FromBody]`               | `[FromForm]`          |
| -------------------------- | --------------------- |
| Usually JSON               | Form data             |
| `application/json`         | `multipart/form-data` |
| DTO containing normal data | Form fields + files   |
| JSON serialization         | Form model binding    |
| Common for POST/PUT        | Common for uploads    |

# 5. `[FromForm]` vs `IFormFile`

These are **not the same thing**.

### `[FromForm]`

Specifies the **binding source**:

```csharp
[FromForm] CreateHospitalRequest request
```

### `IFormFile`

Represents an **uploaded file**:

```csharp
IFormFile file
```

They are often used together:

```csharp
[HttpPost]
public IActionResult Upload(
    [FromForm] IFormFile file)
```

or:

```csharp
public class UploadRequest
{
    public IFormFile File { get; set; }
}
```

```csharp
[HttpPost]
public IActionResult Upload(
    [FromForm] UploadRequest request)
```

# 6. How Model Binding Matches Form Fields

Suppose your model is:

```csharp
public class HospitalRequest
{
    public string Name { get; set; }

    public string City { get; set; }

    public int EstablishedYear { get; set; }
}
```

The client sends:

```text
Name = Apollo Hospital
City = Mumbai
EstablishedYear = 1985
```

ASP.NET Core matches the **form field names** with the model property names:

```text
Name
  ↓
request.Name

City
  ↓
request.City

EstablishedYear
  ↓
request.EstablishedYear
```

The matching is generally case-insensitive, so:

```text
name
Name
NAME
```

can bind to:

```csharp
Name
```

# 7. Nested Objects

You can also bind more complex models.

```csharp
public class CreateHospitalRequest
{
    public string Name { get; set; }

    public AddressRequest Address { get; set; }
}

public class AddressRequest
{
    public string City { get; set; }

    public string State { get; set; }
}
```

Form data can use property paths:

```text
Name = Apollo Hospital
Address.City = Mumbai
Address.State = Maharashtra
```

ASP.NET Core can construct:

```csharp
CreateHospitalRequest
{
    Name = "Apollo Hospital",

    Address =
    {
        City = "Mumbai",
        State = "Maharashtra"
    }
}
```

# 8. `[FromForm]` and Validation

You can use Data Annotations with form-bound models.

```csharp
public class HospitalRequest
{
    [Required]
    public string Name { get; set; }

    [Required]
    public string City { get; set; }

    [Range(1800, 2100)]
    public int EstablishedYear { get; set; }
}
```

Controller:

```csharp
[ApiController]
[Route("api/[controller]")]
public class HospitalsController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(
        [FromForm] HospitalRequest request)
    {
        return Ok(request);
    }
}
```

If required data is missing or invalid, `[ApiController]` integrates model validation and can automatically return:

```http
400 Bad Request
```

# 9. `[FromForm]` in Your Hospital Import Scenario

For the type of API you're building, imagine:

```csharp
public class HospitalImportRequest
{
    [Required]
    public IFormFile File { get; set; }

    public string? Source { get; set; }
}
```

Controller:

```csharp
[HttpPost("import")]
public async Task<IActionResult> Import(
    [FromForm] HospitalImportRequest request)
{
    if (request.File.Length == 0)
    {
        return BadRequest("File is empty.");
    }

    var result = await hospitalImportService
        .ImportHospitals(request.File);

    return Ok(result);
}
```

Request:

```text
POST /api/hospitals/import
Content-Type: multipart/form-data
```

Postman:

| Key    | Type | Value          |
| ------ | ---- | -------------- |
| File   | File | hospitals.xlsx |
| Source | Text | Excel          |

The flow becomes:

```text
             Postman
                │
                │ multipart/form-data
                ↓
      ┌─────────────────────┐
      │ ASP.NET Core        │
      │ Model Binding       │
      └──────────┬──────────┘
                 ↓
     HospitalImportRequest
        ┌────────┴─────────┐
        ↓                  ↓
      File               Source
        ↓                  ↓
    IFormFile           "Excel"
        │
        ↓
 HospitalImportService
        │
        ↓
    ClosedXML
        │
        ↓
      Database
```

That is a realistic enterprise API flow.

# 10. Important: Don't Manually Read `Request.Form`

You may see code like:

```csharp
var form = await Request.ReadFormAsync();

var file = form.Files[0];

var hospitalName = form["hospitalName"];
```

This works, but if you have a known request contract, **model binding is cleaner**:

```csharp
[FromForm] HospitalImportRequest request
```

Then:

```csharp
request.File
request.Source
```

The framework handles the extraction and conversion.

# 11. Multiple Files

You can also upload multiple files.

### Model

```csharp
public class FileUploadRequest
{
    public List<IFormFile> Files { get; set; }
}
```

### Controller

```csharp
[HttpPost("upload")]
public IActionResult Upload(
    [FromForm] FileUploadRequest request)
{
    foreach (var file in request.Files)
    {
        // Process file
    }

    return Ok();
}
```

Postman:

```text
Body → form-data

Files → File → hospitals1.xlsx
Files → File → hospitals2.xlsx
Files → File → hospitals3.xlsx
```

# 12. Interview-Level Understanding

If an interviewer asks:

### **What is `[FromForm]` in ASP.NET Core?**

A strong answer would be:

> `[FromForm]` is an ASP.NET Core model-binding attribute that tells the framework to bind an action parameter or model from form data in the HTTP request. It is commonly used with `multipart/form-data`, especially for file uploads using `IFormFile`. It can also bind regular form fields and files into a DTO.

Then give:

```csharp
public class UploadRequest
{
    public IFormFile File { get; set; }

    public string Description { get; set; }
}

[HttpPost]
public IActionResult Upload(
    [FromForm] UploadRequest request)
{
    ...
}
```

---

## The key thing to remember

Don't memorize `[FromForm]` as simply "for file upload."

Think of it as:

```text
[FromForm]
     ↓
Read values from HTTP form
     ↓
Model Binding
     ↓
DTO / IFormFile
```

And the most common scenario is:

```text
multipart/form-data
       ↓
[FromForm]
       ↓
DTO + IFormFile
       ↓
Controller
       ↓
Application/Service Layer
```

For your interview preparation, **`[FromRoute]`, `[FromQuery]`, `[FromBody]`, and `[FromForm]` together** are the core Model Binding concepts you should be able to explain and implement without hesitation.
