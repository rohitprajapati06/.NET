# Role-Based JWT Authentication in ASP.NET Core Web API

**Role-Based JWT Authentication** means using **roles stored as claims inside a JWT** to control which users can access specific API endpoints.

For example:

```text
Admin → Can Create, Update, Delete
User  → Can View
```

### 1. Add Role Claim to JWT

When generating the JWT, include the user's role:

```csharp
var claims = new[]
{
    new Claim(ClaimTypes.Name, user.Username),
    new Claim(ClaimTypes.Role, user.Role)
};
```

If the user is an Admin, the token contains:

```text
Role = Admin
```

---

### 2. Configure JWT Authentication

```csharp
builder.Services.AddAuthentication(
    JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,

            ValidIssuer = "MyApi",
            ValidAudience = "MyClient",

            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes("my-secret-key"))
        };
    });

builder.Services.AddAuthorization();
```

---

### 3. Restrict API Using `[Authorize]`

Only authenticated users can access:

```csharp
[Authorize]
[HttpGet]
public IActionResult GetProducts()
{
    return Ok(products);
}
```

---

### 4. Restrict API to a Specific Role

Only **Admin** users can access:

```csharp
[Authorize(Roles = "Admin")]
[HttpDelete("{id}")]
public IActionResult DeleteProduct(int id)
{
    return Ok("Product deleted");
}
```

A User with:

```text
Role = User
```

will receive:

```text
403 Forbidden
```

while an unauthenticated request normally receives:

```text
401 Unauthorized
```

### Multiple Roles

You can allow multiple roles:

```csharp
[Authorize(Roles = "Admin,Manager")]
public IActionResult GetReports()
{
    return Ok();
}
```

This means **Admin OR Manager** can access the endpoint.

### Complete Flow

```text
Login
  ↓
Validate Username/Password
  ↓
Get User Role
  ↓
Generate JWT
  ↓
JWT contains:
  Name = Rohit
  Role = Admin
  ↓
Client sends:
Authorization: Bearer <JWT>
  ↓
ASP.NET Core validates JWT
  ↓
[Authorize(Roles = "Admin")]
  ↓
Access Granted / 403 Forbidden
```

### Interview Answer

> **"In role-based JWT authentication, we add the user's role as a role claim when generating the JWT. ASP.NET Core reads that claim after validating the token. We can then use `[Authorize(Roles = "Admin")]` or a policy to restrict specific endpoints to users with the required role."**
