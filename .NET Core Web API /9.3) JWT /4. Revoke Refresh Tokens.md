# Revoke Refresh Tokens in JWT-Based Token Authentication

**Refresh Token Revocation** means making a refresh token invalid before its normal expiration time.

This is important when a user **logs out**, a token is **compromised**, or an administrator wants to **terminate a session**.

### How It Works

Suppose the database contains:

```text
RefreshToken
--------------------------------
Token        : abc123
UserId       : 101
ExpiresAt    : 20-Sep-2026
IsRevoked    : false
```

When the user logs out:

```text
IsRevoked = true
```

Now the token can no longer be used to generate a new JWT.

### Revoke Endpoint

```csharp
[Authorize]
[HttpPost("revoke-refresh-token")]
public IActionResult RevokeRefreshToken(string refreshToken)
{
    var token = db.RefreshTokens
                  .FirstOrDefault(x => x.Token == refreshToken);

    if (token == null)
        return NotFound();

    token.IsRevoked = true;

    db.SaveChanges();

    return Ok("Refresh token revoked.");
}
```

### Validate Before Creating a New JWT

Your refresh-token endpoint should always check:

```csharp
if (token == null ||
    token.IsRevoked ||
    token.ExpiresAt <= DateTime.UtcNow)
{
    return Unauthorized();
}
```

So the flow becomes:

```text
Client
  │
  │ Refresh Token
  ▼
API
  │
  ├── Exists?       ✓
  ├── Not expired?  ✓
  ├── Not revoked?  ✓
  │
  ▼
Generate New JWT
```

If revoked:

```text
Refresh Token
      ↓
IsRevoked = true
      ↓
❌ Unauthorized
```

### When Should Refresh Tokens Be Revoked?

Common cases:

* **User logs out**
* **User changes password**
* **Refresh token is compromised**
* **User account is disabled**
* **Administrator terminates the user's sessions**
* **Refresh-token reuse is detected**

### Important Point About JWT Access Tokens

Revoking a refresh token **does not immediately invalidate an already-issued JWT access token**.

For example:

```text
Access Token → Valid for 15 minutes
Refresh Token → Revoked immediately
```

The existing access token may continue working until its expiration.

That's why access tokens should generally have a **short lifetime**.

### Interview Answer

> **"Refresh token revocation is the process of invalidating a refresh token before it expires. We typically store refresh tokens in a database with a revoked flag. During token refresh, we verify that the token exists, hasn't expired, and hasn't been revoked. When the user logs out or the token is compromised, we mark it as revoked so it cannot be used to obtain another access token."**
