# Resource Server and Client Applications with JWT Authentication

In a JWT-based system, the **Client Application** requests access to a **Resource Server** by presenting a JWT access token.

### Basic Architecture

```text
┌─────────────────┐
│ Client App      │
│ Angular / React │
└────────┬────────┘
         │ 1. Login
         ▼
┌─────────────────┐
│ Authentication  │
│ Server          │
└────────┬────────┘
         │ 2. JWT
         ▼
┌─────────────────┐
│ Client App      │
└────────┬────────┘
         │ 3. JWT in Authorization header
         ▼
┌─────────────────┐
│ Resource Server  │
│ ASP.NET Core API│
└─────────────────┘
```

### 1. Client Application

The **client** is the application requesting protected resources.

Examples:

* Angular application
* React application
* Mobile application
* Another backend service

It sends the JWT with the API request:

```http
GET /api/orders
Authorization: Bearer eyJhbGciOiJIUzI1Ni...
```

---

### 2. Resource Server

The **Resource Server** is the API that contains protected resources/data.

For example:

```csharp
[Authorize]
[HttpGet("orders")]
public IActionResult GetOrders()
{
    return Ok(orders);
}
```

ASP.NET Core validates the JWT before allowing the request to reach the controller.

It checks things such as:

* Signature
* Issuer
* Audience
* Expiration
* Claims

---

### 3. Authentication/Authorization Server

This server is responsible for **authenticating the user** and issuing the access token.

For example:

```text
Username + Password
       ↓
Authentication Server
       ↓
     JWT Token
```

In real-world applications, this might be an identity provider such as Microsoft Entra ID or another OAuth 2.0/OpenID Connect provider.

---

### Complete Flow

```text
1. Client → Authentication Server
              Username + Password

2. Authentication Server
              ↓
           Validates user

3. Authentication Server → Client
              JWT Access Token

4. Client → Resource Server
              Authorization: Bearer <JWT>

5. Resource Server
              ↓
         Validates JWT

6. Resource Server → Client
              Protected Data
```

### Key Difference

| Component                 | Responsibility                                   |
| ------------------------- | ------------------------------------------------ |
| **Client Application**    | Requests resources and sends JWT                 |
| **Authentication Server** | Authenticates user and issues token              |
| **Resource Server**       | Validates token and provides protected resources |

### Simple Real-Time Example

Imagine a **Banking Application**:

```text
Angular Banking App
        ↓
      Login
        ↓
Identity Server
        ↓
    JWT Token
        ↓
Angular App
        ↓
GET /api/accounts
Authorization: Bearer <JWT>
        ↓
Banking API (Resource Server)
        ↓
Account Information
```

**Interview answer:**

> "The client application consumes protected APIs exposed by the resource server. After authentication, the client receives a JWT access token and sends it with API requests using the Bearer scheme. The resource server validates the JWT and, if valid, allows access to the requested resource."
