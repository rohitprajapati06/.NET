# Logging in ASP.NET Core Web API

**Logging** is used to record information about what is happening inside your Web API, such as requests, errors, warnings, and application activities.

ASP.NET Core provides **built-in logging** through `ILogger<T>`.

### 1. Inject `ILogger`

```csharp
public class PatientController : ControllerBase
{
    private readonly ILogger<PatientController> _logger;

    public PatientController(ILogger<PatientController> logger)
    {
        _logger = logger;
    }

    [HttpGet]
    public IActionResult GetPatients()
    {
        _logger.LogInformation("Fetching all patients");

        return Ok();
    }
}
```

### 2. Common Log Levels

| Level         | Purpose                                           |
| ------------- | ------------------------------------------------- |
| `Trace`       | Very detailed debugging information               |
| `Debug`       | Information useful during development             |
| `Information` | Normal application activity                       |
| `Warning`     | Unexpected situation but application can continue |
| `Error`       | An operation failed                               |
| `Critical`    | Serious failure affecting the application         |

Example:

```csharp
_logger.LogInformation("Patient {PatientId} retrieved", patientId);

_logger.LogWarning("Patient {PatientId} was not found", patientId);

_logger.LogError(exception, "Error while retrieving patient");
```

### 3. Configure Logging

In `appsettings.json`:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

This controls **which log levels are recorded**.

### 4. Logging Providers

ASP.NET Core can send logs to different destinations through **logging providers**, such as:

* Console
* Debug
* EventSource
* Windows Event Log
* Third-party providers like Serilog

### In short

```text
Controller/Service
       ↓
   ILogger<T>
       ↓
 Logging Providers
       ↓
Console / File / Database / Application Insights
```

**Best practice:** Use `ILogger<T>` instead of `Console.WriteLine()` because it supports log levels, structured logging, filtering, and different production logging providers.
