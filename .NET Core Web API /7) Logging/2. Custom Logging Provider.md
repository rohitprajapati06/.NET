# Custom Logging Provider in ASP.NET Core Web API

A **Custom Logging Provider** allows you to control **where and how logs are stored** instead of using built-in providers like Console or Debug.

For example, you can create a provider that writes logs to a **custom file, database, or external system**.

### Basic Architecture

```text
ILogger<T>
    ↓
Custom Logger
    ↓
Custom Logger Provider
    ↓
Your destination
(File / DB / External Service)
```

### 1. Create Custom Logger

```csharp
public class CustomLogger : ILogger
{
    public IDisposable? BeginScope<TState>(TState state)
        => null;

    public bool IsEnabled(LogLevel logLevel)
        => logLevel != LogLevel.None;

    public void Log<TState>(
        LogLevel logLevel,
        EventId eventId,
        TState state,
        Exception? exception,
        Func<TState, Exception?, string> formatter)
    {
        var message = formatter(state, exception);

        File.AppendAllText(
            "logs.txt",
            $"{DateTime.Now}: {logLevel} - {message}\n");
    }
}
```

### 2. Create Logger Provider

```csharp
public class CustomLoggerProvider : ILoggerProvider
{
    public ILogger CreateLogger(string categoryName)
    {
        return new CustomLogger();
    }

    public void Dispose()
    {
    }
}
```

### 3. Register Provider

In `Program.cs`:

```csharp
builder.Logging.ClearProviders();

builder.Logging.AddProvider(new CustomLoggerProvider());
```

Now when you use:

```csharp
_logger.LogInformation("Patient created successfully");
```

the log will be handled by your **CustomLogger**.

### Why use a Custom Logging Provider?

* Store logs in a custom **database**
* Write logs to a specific **file format**
* Send logs to an external logging system
* Implement custom filtering/formatting
* Integrate with enterprise-specific logging infrastructure

> In real-world enterprise applications, libraries such as **Serilog**, **NLog**, or **Application Insights** are generally preferred over building a custom provider from scratch.
