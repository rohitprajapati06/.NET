# Client Application Two using ASP.NET Core MVC

In an **SSO architecture**, Client Application Two is another ASP.NET Core MVC application that uses the **same Authentication Server / Identity Provider** as Client Application One.

### Architecture

```text
                 Authentication Server
                    (Identity Provider)
                           │
             ┌─────────────┴─────────────┐
             ↓                           ↓
      Client Application 1       Client Application 2
        ASP.NET MVC                 ASP.NET MVC
             │                           │
             └─────────────┬─────────────┘
                           ↓
                    Resource Server
                    ASP.NET Core API
```

### 1. Configure OpenID Connect

Client Application Two is registered separately with the Identity Provider:

```csharp
builder.Services
    .AddAuthentication(options =>
    {
        options.DefaultScheme =
            CookieAuthenticationDefaults.AuthenticationScheme;

        options.DefaultChallengeScheme =
            OpenIdConnectDefaults.AuthenticationScheme;
    })
    .AddCookie()
    .AddOpenIdConnect(options =>
    {
        options.Authority = "https://your-identity-provider";
        options.ClientId = "client-app-two";
        options.ClientSecret = "client-secret";
        options.ResponseType = "code";
        options.SaveTokens = true;
    });
```

### 2. Protect the Controller

```csharp
[Authorize]
public class DashboardController : Controller
{
    public IActionResult Index()
    {
        return View();
    }
}
```

### 3. SSO Flow

If the user has **already logged in through Client Application One**:

```text
Client App 1
     ↓
Identity Provider
     ↓
User Login ✓
     ↓
Client App 1
     
User opens Client App 2
     ↓
Identity Provider
     ↓
Existing session detected
     ↓
No login required
     ↓
Client App 2 ✓
```

The important point is that **Client Application Two does not share the authentication cookie of Client Application One**. Both applications trust the **same Identity Provider**, which maintains the central SSO session.

### Interview Answer

> **Client Application Two is another ASP.NET Core MVC application registered with the same Identity Provider. It uses OpenID Connect for authentication. If the user has already authenticated through Client Application One, the Identity Provider recognizes the existing session and authenticates the user without asking for credentials again. This is how SSO provides a seamless login experience across multiple applications.**
