# API Versioning in ASP.NET Core Minimal API

**API Versioning** allows you to maintain multiple versions of an API while clients can continue using an older contract.

For example:

```text
/api/v1/products
/api/v2/products
```

This is useful when you introduce **breaking changes** but cannot immediately migrate all clients.

Minimal APIs support API versioning through the **`Asp.Versioning.Http`** package. ([Microsoft Learn][1])

---

## 1. Install the Package

Install:

```bash
dotnet add package Asp.Versioning.Http
```

This package provides versioning support specifically for HTTP APIs, including Minimal APIs.

---

## 2. Configure API Versioning

In `Program.cs`:

```csharp
using Asp.Versioning;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddApiVersioning();

var app = builder.Build();
```

Now you can configure version-aware endpoints.

---

# 3. Version Using URL Path

A common approach is:

```text
/api/v1/products
/api/v2/products
```

Create a version set:

```csharp
var versionSet = app.NewApiVersionSet()
    .HasApiVersion(new ApiVersion(1, 0))
    .HasApiVersion(new ApiVersion(2, 0))
    .ReportApiVersions()
    .Build();
```

Then map the endpoints:

```csharp
app.MapGet("/api/v{version:apiVersion}/products", () =>
{
    return Results.Ok("Products API");
})
.WithApiVersionSet(versionSet)
.MapToApiVersion(1.0);
```

For V2:

```csharp
app.MapGet("/api/v{version:apiVersion}/products", () =>
{
    return Results.Ok("Products API V2");
})
.WithApiVersionSet(versionSet)
.MapToApiVersion(2.0);
```

Requests:

```text
GET /api/v1/products
GET /api/v2/products
```

---

# 4. Different Responses for Different Versions

This is where versioning becomes useful.

### V1

```csharp
app.MapGet("/api/v{version:apiVersion}/products", () =>
{
    return Results.Ok(new
    {
        Id = 1,
        Name = "Laptop"
    });
})
.WithApiVersionSet(versionSet)
.MapToApiVersion(1.0);
```

### V2

```csharp
app.MapGet("/api/v{version:apiVersion}/products", () =>
{
    return Results.Ok(new
    {
        Id = 1,
        Name = "Laptop",
        Price = 50000
    });
})
.WithApiVersionSet(versionSet)
.MapToApiVersion(2.0);
```

Now:

```text
/api/v1/products
        ↓
Id + Name

/api/v2/products
        ↓
Id + Name + Price
```

The older client can continue using V1 while newer clients use V2.

---

# 5. Query String Versioning

You can also version using a query string:

```text
/api/products?api-version=1.0
/api/products?api-version=2.0
```

Configure:

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader =
        new QueryStringApiVersionReader("api-version");
});
```

Then:

```csharp
var versionSet = app.NewApiVersionSet()
    .HasApiVersion(1.0)
    .HasApiVersion(2.0)
    .Build();
```

Endpoint:

```csharp
app.MapGet("/api/products", () =>
{
    return Results.Ok("Products V1");
})
.WithApiVersionSet(versionSet)
.MapToApiVersion(1.0);
```

Request:

```text
GET /api/products?api-version=1.0
```

---

# 6. Header Versioning

Another approach is to send the version in a header.

For example:

```text
X-API-Version: 1.0
```

Configure:

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader =
        new HeaderApiVersionReader("X-API-Version");
});
```

Request:

```http
GET /api/products
X-API-Version: 1.0
```

---

# 7. Multiple Versioning Strategies

You can also combine readers:

```csharp
builder.Services.AddApiVersioning(options =>
{
    options.ApiVersionReader =
        ApiVersionReader.Combine(
            new QueryStringApiVersionReader("api-version"),
            new HeaderApiVersionReader("X-API-Version")
        );
});
```

Now the API can accept either:

```text
/api/products?api-version=1.0
```

or:

```http
X-API-Version: 1.0
```

---

# 8. Report Supported Versions

You can configure:

```csharp
var versionSet = app.NewApiVersionSet()
    .HasApiVersion(1.0)
    .HasApiVersion(2.0)
    .ReportApiVersions()
    .Build();
```

The API can then communicate supported/deprecated versions through response headers.

This is useful when managing API lifecycle and migrations.

---

# 9. Recommended Approach

For a public API, a clear versioned URL such as:

```text
/api/v1/products
/api/v2/products
```

is easy for clients and developers to understand.

A typical structure:

```text
Client
   │
   ├── /api/v1/products
   │        ↓
   │      V1 Endpoint
   │
   └── /api/v2/products
            ↓
          V2 Endpoint
```

Both versions can share the same service/database layer when appropriate:

```text
             ┌── V1 Endpoint ──┐
Client ──────┤                  ├── Service ── EF Core ── DB
             └── V2 Endpoint ──┘
```

---

## API Versioning vs Endpoint Routing

Remember:

```text
Routing
→ Determines which endpoint handles the request.

API Versioning
→ Determines which version of that API contract the client is requesting.
```

> **API Versioning in Minimal APIs allows us to maintain multiple versions of an API without breaking existing clients.
