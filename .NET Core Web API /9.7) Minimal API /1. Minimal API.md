# Minimal API in ASP.NET Core

**Minimal API** is a lightweight way to build HTTP APIs in ASP.NET Core with **minimal code and fewer abstractions**. Instead of using Controllers, you define endpoints directly in `Program.cs`.

It is commonly used for **small services, microservices, prototypes, and simple APIs**.

---

## 1. Traditional Controller API

Normally, we create a controller:

```csharp
[ApiController]
[Route("api/products")]
public class ProductsController : ControllerBase
{
    [HttpGet]
    public IActionResult GetProducts()
    {
        return Ok(new[] { "Laptop", "Mobile", "Tablet" });
    }
}
```

This requires a **Controller class, attributes, and action method**.

---

## 2. Minimal API

The same API can be written directly in `Program.cs`:

```csharp
var builder = WebApplication.CreateBuilder(args);

var app = builder.Build();

app.MapGet("/api/products", () =>
{
    return new[] { "Laptop", "Mobile", "Tablet" };
});

app.Run();
```

That's the basic idea of a Minimal API.

---

# 3. HTTP Methods

Minimal APIs provide methods for different HTTP operations:

```csharp
app.MapGet("/products", () => "Get Products");

app.MapPost("/products", () => "Create Product");

app.MapPut("/products/{id}", (int id) => $"Update Product {id}");

app.MapDelete("/products/{id}", (int id) => $"Delete Product {id}");
```

| Method | Minimal API   |
| ------ | ------------- |
| GET    | `MapGet()`    |
| POST   | `MapPost()`   |
| PUT    | `MapPut()`    |
| DELETE | `MapDelete()` |
| PATCH  | `MapPatch()`  |

---

# 4. Route Parameters

You can capture values directly from the route.

```csharp
app.MapGet("/products/{id}", (int id) =>
{
    return $"Product ID: {id}";
});
```

Request:

```text
GET /products/10
```

Response:

```text
Product ID: 10
```

---

# 5. Query Parameters

Query parameters can also be bound automatically.

```csharp
app.MapGet("/products", (string name) =>
{
    return $"Searching for {name}";
});
```

Request:

```text
GET /products?name=Laptop
```

---

# 6. Request Body

For POST requests, Minimal APIs can bind the request body to an object.

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

```csharp
app.MapPost("/products", (Product product) =>
{
    return Results.Ok(product);
});
```

JSON:

```json
{
    "id": 1,
    "name": "Laptop",
    "price": 50000
}
```

---

# 7. Returning HTTP Status Codes

Minimal APIs provide the `Results` class:

```csharp
app.MapGet("/products/{id}", (int id) =>
{
    if (id <= 0)
        return Results.BadRequest("Invalid product ID");

    return Results.Ok(new
    {
        Id = id,
        Name = "Laptop"
    });
});
```

Common results:

```csharp
Results.Ok()
Results.Created()
Results.BadRequest()
Results.NotFound()
Results.Unauthorized()
Results.NoContent()
```

---

# 8. Dependency Injection

Minimal APIs support ASP.NET Core's built-in **Dependency Injection**.

For example:

```csharp
builder.Services.AddScoped<IProductService, ProductService>();
```

Then inject it directly into the endpoint:

```csharp
app.MapGet("/products", (IProductService service) =>
{
    return service.GetProducts();
});
```

You don't need to manually resolve the service from `IServiceProvider`.

---

# 9. Minimal API with Entity Framework Core

A `DbContext` can also be injected:

```csharp
app.MapGet("/products", async (ApplicationDbContext context) =>
{
    var products = await context.Products.ToListAsync();

    return Results.Ok(products);
});
```

This makes Minimal APIs suitable for real database-backed APIs as well.

---

# 10. Route Groups

For larger Minimal APIs, `MapGroup()` helps organize endpoints.

```csharp
var products = app.MapGroup("/api/products");

products.MapGet("/", GetProducts);
products.MapGet("/{id}", GetProductById);
products.MapPost("/", CreateProduct);
products.MapDelete("/{id}", DeleteProduct);
```

This prevents `Program.cs` from becoming difficult to manage.

---

# 11. Minimal API vs Controller API

| Feature            | Minimal API                     | Controller API  |
| ------------------ | ------------------------------- | --------------- |
| Code               | Less                            | More            |
| Controllers        | ❌                               | ✅               |
| Attributes         | Minimal                         | Commonly used   |
| DI                 | ✅                               | ✅               |
| EF Core            | ✅                               | ✅               |
| Model Binding      | ✅                               | ✅               |
| Validation         | ✅                               | ✅               |
| Filters            | Limited/different approach      | ✅               |
| Large applications | Possible, requires organization | Often preferred |
| Microservices      | Very suitable                   | Suitable        |
| Simple APIs        | Excellent                       | More overhead   |

---

## Interview Definition

> **Minimal API is a lightweight approach in ASP.NET Core for building HTTP APIs with minimal boilerplate code. Instead of using controllers and action methods, endpoints are directly mapped using methods such as `MapGet`, `MapPost`, `MapPut`, and `MapDelete`. It supports dependency injection, model binding, authentication, authorization, Entity Framework Core, and other ASP.NET Core features.**

### Key point to remember

**Controller API:**

```text
Request → Controller → Action → Service → Repository → Database
```

**Minimal API:**

```text
Request → Endpoint → Service → Repository → Database
```

The major difference is **how the HTTP endpoints are defined**, not that Minimal APIs are a completely different framework.
