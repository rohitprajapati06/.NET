# JWT Authentication in ASP.NET Core Minimal API

**JWT (JSON Web Token) Authentication** is used to authenticate clients in a Minimal API without maintaining server-side session state.

The basic flow is:

```text
Client
  │
  │ Login
  ▼
Authentication API
  │
  │ JWT
  ▼
Client
  │
  │ Authorization: Bearer <token>
  ▼
Minimal API
  │
  ▼
JWT Authentication Middleware
  │
  ▼
Endpoint
```

---

## 1. Install JWT Authentication Package

```bash
dotnet add package Microsoft.AspNetCore.Authentication.JwtBearer
```

---

## 2. Configure JWT Authentication

In `Program.cs`:

```csharp
using Microsoft.AspNetCore.Authentication.JwtBearer;
using Microsoft.IdentityModel.Tokens;
using System.Text;

var builder = WebApplication.CreateBuilder(args);

builder.Services
    .AddAuthentication(JwtBearerDefaults.AuthenticationScheme)
    .AddJwtBearer(options =>
    {
        options.TokenValidationParameters = new TokenValidationParameters
        {
            ValidateIssuer = true,
            ValidateAudience = true,
            ValidateLifetime = true,
            ValidateIssuerSigningKey = true,

            ValidIssuer = builder.Configuration["Jwt:Issuer"],
            ValidAudience = builder.Configuration["Jwt:Audience"],

            IssuerSigningKey = new SymmetricSecurityKey(
                Encoding.UTF8.GetBytes(
                    builder.Configuration["Jwt:Key"]!))
        };
    });

builder.Services.AddAuthorization();

var app = builder.Build();

app.UseAuthentication();
app.UseAuthorization();
```

### Important order

```csharp
app.UseAuthentication();
app.UseAuthorization();
```

Authentication should run before authorization.

# 3. Configure JWT Settings

`appsettings.json`:

```json
{
  "Jwt": {
    "Key": "your-long-secret-key-here",
    "Issuer": "MyApi",
    "Audience": "MyApiUsers"
  }
}
```

For production, don't store sensitive signing keys directly in `appsettings.json`. Use a secure secret-management mechanism such as environment variables or Azure Key Vault.

---

# 4. Protect a Minimal API Endpoint

Use `.RequireAuthorization()`:

```csharp
app.MapGet("/api/products", () =>
{
    return Results.Ok(new[]
    {
        "Laptop",
        "Mobile",
        "Tablet"
    });
})
.RequireAuthorization();
```

Now the endpoint requires a valid JWT.

Without a token:

```text
401 Unauthorized
```

With a valid token:

```text
200 OK
```

# 5. Public Endpoint

You don't need authorization on every endpoint.

For example, login can remain public:

```csharp
app.MapPost("/api/login", () =>
{
    // Validate username/password
    // Generate JWT

    return Results.Ok(new
    {
        Token = "generated-jwt-token"
    });
});
```

Then protect other endpoints:

```csharp
app.MapGet("/api/profile", () =>
{
    return Results.Ok("User profile");
})
.RequireAuthorization();
```

# 6. Reading User Information from JWT

Minimal API can access `HttpContext.User`.

```csharp
app.MapGet("/api/profile", (HttpContext httpContext) =>
{
    var userName = httpContext.User.Identity?.Name;

    return Results.Ok(new
    {
        UserName = userName
    });
})
.RequireAuthorization();
```

You can also read claims:

```csharp
app.MapGet("/api/profile", (HttpContext context) =>
{
    var userId = context.User.FindFirst("userId")?.Value;
    var role = context.User.FindFirst("role")?.Value;

    return Results.Ok(new
    {
        UserId = userId,
        Role = role
    });
})
.RequireAuthorization();
```

# 7. Role-Based Authorization

Suppose your JWT contains:

```text
Role = Admin
```

Configure an authorization policy:

```csharp
builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("AdminOnly", policy =>
        policy.RequireRole("Admin"));
});
```

Then:

```csharp
app.MapDelete("/api/products/{id}", (int id) =>
{
    return Results.Ok($"Product {id} deleted");
})
.RequireAuthorization("AdminOnly");
```

Only users with the required role can access this endpoint.

---

# 8. Authorization on Route Groups

This is very useful in Minimal APIs.

```csharp
var products = app.MapGroup("/api/products")
    .RequireAuthorization();

products.MapGet("/", () =>
{
    return Results.Ok("All products");
});

products.MapGet("/{id}", (int id) =>
{
    return Results.Ok($"Product {id}");
});

products.MapPost("/", () =>
{
    return Results.Ok("Product created");
});
```

All endpoints inside the group require authentication.

You can also create an admin group:

```csharp
var admin = app.MapGroup("/api/admin")
    .RequireAuthorization("AdminOnly");
```

# 9. JWT Authentication vs Authorization

This distinction is important for interviews.

### Authentication

**Who are you?**

```text
JWT → Validate token → Identify user
```

### Authorization

**What are you allowed to do?**

```text
User → Role/Policy → Allow or Deny
```

In ASP.NET Core:

```text
UseAuthentication()
        ↓
Who is the user?
        ↓
UseAuthorization()
        ↓
What can the user access?
        ↓
Endpoint
```

# 10. Typical Request

The client sends:

```http
GET /api/products
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
```

ASP.NET Core:

```text
Authorization Header
        ↓
JWT Bearer Handler
        ↓
Validate Signature
        ↓
Validate Issuer
        ↓
Validate Audience
        ↓
Validate Expiration
        ↓
Create ClaimsPrincipal
        ↓
Authorization
        ↓
Minimal API Endpoint
```

# 11. JWT Generation

Authentication is normally handled by a login/authentication service.

Conceptually:

```csharp
var claims = new[]
{
    new Claim(ClaimTypes.NameIdentifier, user.Id.ToString()),
    new Claim(ClaimTypes.Name, user.UserName!),
    new Claim(ClaimTypes.Role, user.Role)
};

var key = new SymmetricSecurityKey(
    Encoding.UTF8.GetBytes(configuration["Jwt:Key"]!));

var credentials = new SigningCredentials(
    key,
    SecurityAlgorithms.HmacSha256);

var token = new JwtSecurityToken(
    issuer: configuration["Jwt:Issuer"],
    audience: configuration["Jwt:Audience"],
    claims: claims,
    expires: DateTime.UtcNow.AddMinutes(30),
    signingCredentials: credentials);

var jwt = new JwtSecurityTokenHandler()
    .WriteToken(token);
```

The generated token is returned to the client.

# 12. Complete Minimal API Structure

A simple application could look like:

```text
Program.cs
│
├── Authentication
│     └── JWT configuration
│
├── Authorization
│     └── Policies / Roles
│
├── Login Endpoint
│     └── Generates JWT
│
└── Protected Endpoints
      ├── GET /api/products
      ├── POST /api/products
      └── DELETE /api/products
```

For a larger application, keep JWT generation and user validation in a separate **authentication service**, rather than putting that logic directly in `Program.cs`.

## Interview Answer

> **JWT authentication in ASP.NET Core Minimal API is implemented using the JWT Bearer authentication handler. We configure `AddAuthentication().AddJwtBearer()`, define token validation parameters such as issuer, audience, lifetime, and signing key, and then enable `UseAuthentication()` and `UseAuthorization()`. Minimal API endpoints can be protected using `.RequireAuthorization()`, authorization policies, or roles. The client sends the JWT using the `Authorization: Bearer <token>` header, and ASP.NET Core validates the token before allowing access to the endpoint.**

### Key things to remember

```text
AddAuthentication()
       ↓
AddJwtBearer()
       ↓
UseAuthentication()
       ↓
UseAuthorization()
       ↓
RequireAuthorization()
```

**Authentication = Who are you?**
**Authorization = What are you allowed to access?**
