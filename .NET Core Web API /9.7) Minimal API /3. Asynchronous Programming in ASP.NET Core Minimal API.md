# Asynchronous Programming in ASP.NET Core Minimal API

**Asynchronous programming** allows an ASP.NET Core Minimal API to handle I/O operations without blocking a thread while waiting for operations such as **database queries, HTTP calls, file operations, or external services**.

The main keywords are:

```text
async
await
Task
Task<T>
CancellationToken
```

---

## 1. Basic Async Minimal API

A synchronous endpoint:

```csharp
app.MapGet("/products", () =>
{
    return productService.GetProducts();
});
```

An asynchronous endpoint:

```csharp
app.MapGet("/products", async () =>
{
    var products = await productService.GetProductsAsync();

    return Results.Ok(products);
});
```

Here:

* `async` → allows the method to use `await`
* `await` → waits for the asynchronous operation without blocking the thread
* `Task<T>` → represents an asynchronous operation that eventually produces a result

---

## 2. Async with Entity Framework Core

This is one of the most common scenarios.

```csharp
app.MapGet("/products", async (AppDbContext context) =>
{
    var products = await context.Products
        .ToListAsync();

    return Results.Ok(products);
});
```

Instead of:

```csharp
var products = context.Products.ToList();
```

use:

```csharp
var products = await context.Products.ToListAsync();
```

for database I/O.

---

## 3. Async POST Request

```csharp
app.MapPost("/products", async (
    Product product,
    AppDbContext context) =>
{
    context.Products.Add(product);

    await context.SaveChangesAsync();

    return Results.Created(
        $"/products/{product.Id}",
        product);
});
```

`SaveChangesAsync()` allows the database operation to execute asynchronously.

# 4. Async Service Layer

For a real application, business logic should usually be separated from the endpoint.

```csharp
public interface IProductService
{
    Task<List<Product>> GetProductsAsync();
}
```

Implementation:

```csharp
public class ProductService : IProductService
{
    private readonly AppDbContext _context;

    public ProductService(AppDbContext context)
    {
        _context = context;
    }

    public async Task<List<Product>> GetProductsAsync()
    {
        return await _context.Products
            .ToListAsync();
    }
}
```

Minimal API:

```csharp
app.MapGet("/products", async (
    IProductService service) =>
{
    var products = await service.GetProductsAsync();

    return Results.Ok(products);
});
```

# 5. Multiple Async Operations

Suppose you need to call two independent APIs.

Instead of:

```csharp
var products = await GetProductsAsync();
var customers = await GetCustomersAsync();
```

you can execute them concurrently:

```csharp
var productsTask = GetProductsAsync();
var customersTask = GetCustomersAsync();

await Task.WhenAll(
    productsTask,
    customersTask);

var products = await productsTask;
var customers = await customersTask;
```

This can reduce total waiting time when the operations are independent.

---

# 6. CancellationToken

Minimal APIs can receive a `CancellationToken` automatically.

```csharp
app.MapGet("/products", async (
    AppDbContext context,
    CancellationToken cancellationToken) =>
{
    var products = await context.Products
        .ToListAsync(cancellationToken);

    return Results.Ok(products);
});
```

If the client disconnects or the request is cancelled, the operation can be cancelled rather than continuing unnecessarily.

---

# 7. Async External API Call

For example, calling another service using `HttpClient`:

```csharp
app.MapGet("/external-products", async (
    HttpClient httpClient) =>
{
    var response = await httpClient
        .GetAsync("https://example.com/products");

    var data = await response.Content
        .ReadAsStringAsync();

    return Results.Ok(data);
});
```

In production, use a properly configured `HttpClient` through `IHttpClientFactory`.

---

# 8. Don't Block Async Code

Avoid:

```csharp
var result = GetProductsAsync().Result;
```

or:

```csharp
var result = GetProductsAsync().GetAwaiter().GetResult();
```

Prefer:

```csharp
var result = await GetProductsAsync();
```

### Why?

Blocking an asynchronous operation can:

* waste thread-pool threads
* reduce scalability
* potentially cause deadlocks in some application contexts

---

# 9. Async Does NOT Mean "Creates a New Thread"

This is an important interview concept.

When you write:

```csharp
await context.Products.ToListAsync();
```

ASP.NET Core does **not necessarily create a new thread**.

For I/O-bound operations, the current thread can be released while the database operation is pending.

Conceptually:

```text
Request
   ↓
Endpoint
   ↓
Database Call
   ↓
Thread is free
   ↓
Database completes
   ↓
Continuation resumes
   ↓
Response
```

This is why asynchronous I/O improves server scalability.

---

# 10. Async vs Parallelism

These are different concepts.

### Async

Primarily helps with **I/O-bound operations**:

```text
Database
HTTP API
File I/O
Network
```

### Parallelism

Primarily involves executing **CPU-bound work concurrently**:

```text
Image processing
Complex calculations
Data processing
```

So:

> **Async is mainly about not blocking while waiting; parallelism is about doing work simultaneously.**

---

# 11. Recommended Minimal API Pattern

For your ASP.NET Core projects, a good structure is:

```text
Minimal API Endpoint
        ↓
Service
        ↓
Repository / EF Core
        ↓
Database
```

And make I/O operations asynchronous throughout the call chain:

```text
Endpoint
   ↓ await
Service
   ↓ await
Repository
   ↓ await
EF Core
   ↓
Database
```

For example:

```csharp
app.MapGet("/doctors", async (
    IDoctorService service,
    CancellationToken cancellationToken) =>
{
    var doctors = await service
        .GetDoctorsAsync(cancellationToken);

    return Results.Ok(doctors);
});
```

---

## Interview Answer

> **Asynchronous programming in ASP.NET Core Minimal API is used to perform I/O-bound operations without blocking request threads. We use `async` and `await` with APIs such as EF Core's `ToListAsync()` and `SaveChangesAsync()`. This improves scalability because threads are not blocked while waiting for database, network, or other I/O operations. We can also use `CancellationToken` to cancel long-running operations when a request is cancelled.**
