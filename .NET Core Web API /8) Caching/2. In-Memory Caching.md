# In-Memory Caching in ASP.NET Core Web API

**In-Memory Caching** stores frequently used data directly in the **memory (RAM) of the API server** using `IMemoryCache`.

It avoids repeatedly querying the database, improving performance and reducing database load.

### How it works

```text
Client Request
      ↓
   API
      ↓
Check Cache
   ↙       ↘
Found      Not Found
 ↓            ↓
Return     Database
Data          ↓
           Store in Cache
                ↓
             Return Data
```

### 1. Register Memory Cache

In `Program.cs`:

```csharp
builder.Services.AddMemoryCache();
```

### 2. Inject `IMemoryCache`

```csharp
private readonly IMemoryCache _cache;

public ProductController(IMemoryCache cache)
{
    _cache = cache;
}
```

### 3. Get and Set Cache

```csharp
[HttpGet]
public async Task<IActionResult> GetProducts()
{
    if (!_cache.TryGetValue("products", out List<Product>? products))
    {
        products = await _context.Products.ToListAsync();

        _cache.Set("products", products, TimeSpan.FromMinutes(10));
    }

    return Ok(products);
}
```

### What happens?

**First request:**

```text
API → Cache ❌ → Database → Cache → Response
```

**Next requests:**

```text
API → Cache ✅ → Response
```

### Cache Expiration

You can specify how long data remains cached:

```csharp
_cache.Set("products", products, TimeSpan.FromMinutes(10));
```

You can also use options:

```csharp
var options = new MemoryCacheEntryOptions
{
    AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10),
    SlidingExpiration = TimeSpan.FromMinutes(2)
};

_cache.Set("products", products, options);
```

* **Absolute expiration** → Cache expires after a fixed time.
* **Sliding expiration** → Expiration time resets whenever the cached item is accessed.

### Important Limitation

In-memory cache belongs to **one application/server instance**.

If you have:

```text
Server 1 → Cache A
Server 2 → Cache B
Server 3 → Cache C
```

The caches are **not shared**.

For multiple servers, use **Distributed Caching (e.g., Redis)**.

**Interview point:** `IMemoryCache` is best suited for data that is frequently accessed, relatively small, and safe to keep in the memory of a single API instance.
