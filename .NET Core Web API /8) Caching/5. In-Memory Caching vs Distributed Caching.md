# In-Memory Caching vs Distributed Caching

| Feature              | In-Memory Caching               | Distributed Caching                                                 |
| -------------------- | ------------------------------- | ------------------------------------------------------------------- |
| **Interface**        | `IMemoryCache`                  | `IDistributedCache`                                                 |
| **Storage**          | Application server's RAM        | External/shared cache                                               |
| **Multiple Servers** | ❌ Each server has its own cache | ✅ All servers can share cache                                       |
| **Performance**      | Very fast                       | Slightly slower due to network call                                 |
| **Scalability**      | Limited                         | Highly scalable                                                     |
| **Data Sharing**     | ❌ Not shared                    | ✅ Shared                                                            |
| **Examples**         | `IMemoryCache`                  | Redis, SQL Server                                                   |
| **Best For**         | Single-server applications      | Load-balanced/distributed applications                              |
| **Cache Loss**       | Lost when application restarts  | Generally survives API restart, depending on provider/configuration |

### Example

**In-Memory:**

```csharp
builder.Services.AddMemoryCache();
```

```text
API Server
 └── RAM
     └── Cache
```

**Distributed (Redis):**

```csharp
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = "localhost:6379";
});
```

```text
          ┌── API Server 1 ──┐
          │                  │
Client → Load Balancer       ├──→ Redis Cache
          │                  │
          └── API Server 2 ──┘
```

### Key Difference

> **In-Memory Cache** stores data inside the API application's memory, while **Distributed Cache** stores data in a shared external cache that can be accessed by multiple API instances.

**Interview tip:** For a production Web API running on multiple instances, **Redis distributed caching** is generally preferred over `IMemoryCache`.
