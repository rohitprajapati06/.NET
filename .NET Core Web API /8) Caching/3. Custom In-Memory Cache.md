# Custom In-Memory Cache in ASP.NET Core Web API

A **Custom In-Memory Cache** means creating your own cache service on top of `IMemoryCache` instead of directly using `IMemoryCache` inside controllers.

This follows **Separation of Concerns** and makes caching reusable.

### 1. Create Cache Interface

```csharp
public interface ICacheService
{
    T? Get<T>(string key);
    void Set<T>(string key, T value, TimeSpan expiration);
    void Remove(string key);
}
```

### 2. Implement Cache Service

```csharp
public class CacheService : ICacheService
{
    private readonly IMemoryCache _cache;

    public CacheService(IMemoryCache cache)
    {
        _cache = cache;
    }

    public T? Get<T>(string key)
    {
        return _cache.TryGetValue(key, out T? value)
            ? value
            : default;
    }

    public void Set<T>(string key, T value, TimeSpan expiration)
    {
        _cache.Set(key, value, expiration);
    }

    public void Remove(string key)
    {
        _cache.Remove(key);
    }
}
```

### 3. Register Services

```csharp
builder.Services.AddMemoryCache();
builder.Services.AddSingleton<ICacheService, CacheService>();
```

`IMemoryCache` and the custom cache service are generally registered as **Singleton**, because the cache needs to be shared across requests within the same application instance.

### 4. Use in Controller

```csharp
private readonly ICacheService _cache;

public ProductController(ICacheService cache)
{
    _cache = cache;
}

[HttpGet]
public async Task<IActionResult> GetProducts()
{
    var products = _cache.Get<List<Product>>("products");

    if (products == null)
    {
        products = await _context.Products.ToListAsync();

        _cache.Set(
            "products",
            products,
            TimeSpan.FromMinutes(10));
    }

    return Ok(products);
}
```

### Why create a custom cache?

| Direct `IMemoryCache`      | Custom Cache Service    |
| -------------------------- | ----------------------- |
| Cache logic in controllers | Cache logic centralized |
| Difficult to reuse         | Easily reusable         |
| More tightly coupled       | Better abstraction      |
| Harder to test             | Easier to mock/test     |

**Interview point:** A custom cache service is an abstraction over `IMemoryCache` that keeps caching logic separate from controllers/business logic.
