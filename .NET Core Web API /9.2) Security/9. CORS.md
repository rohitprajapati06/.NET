# CORS in ASP.NET Core Web API

**CORS (Cross-Origin Resource Sharing)** is a browser security mechanism that controls whether a frontend from one **origin** can make requests to an ASP.NET Core Web API hosted on a different origin.

Example:

```text
Frontend:  https://myapp.com
API:       https://api.myapp.com
```

These are different origins, so CORS rules apply.

### 1. Configure CORS

In `Program.cs`:

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowFrontend", policy =>
    {
        policy.WithOrigins("https://myapp.com")
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});
```

### 2. Enable CORS

```csharp
app.UseCors("AllowFrontend");

app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();
```

### Common CORS Methods

```csharp
policy.WithOrigins("https://myapp.com") // Specific origin
      .AllowAnyHeader()                 // Any request header
      .AllowAnyMethod();                // GET, POST, PUT, DELETE, etc.
```

You can also allow multiple origins:

```csharp
policy.WithOrigins(
    "https://myapp.com",
    "https://admin.myapp.com");
```

### Allow Everything — Development Only

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("AllowAll", policy =>
    {
        policy.AllowAnyOrigin()
              .AllowAnyHeader()
              .AllowAnyMethod();
    });
});
```

Avoid `AllowAnyOrigin()` in production unless you genuinely intend the API to be publicly callable from any browser origin.

### Important: CORS ≠ Authentication

CORS **does not authenticate or authorize users**.

```text
CORS           → Which browser origins can call the API?
Authentication → Who is the caller?
Authorization  → What can the caller access?
```

**Interview point:** CORS is primarily a **browser-enforced security mechanism**. It doesn't prevent non-browser clients such as Postman or backend services from calling your API.
