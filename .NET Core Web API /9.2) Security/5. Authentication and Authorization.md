# Authentication and Authorization in ASP.NET Core Web API

These are two different security concepts:

### 1. Authentication — **"Who are you?"**

Authentication verifies the **identity of the user/client**.

Common methods:

* JWT Bearer Authentication
* Cookie Authentication
* OAuth 2.0 / OpenID Connect
* API Keys
* HMAC Authentication

Example:

```text
Client → Login → Username + Password
                 ↓
             API validates
                 ↓
          JWT Access Token
```

The client then sends:

```http
Authorization: Bearer <JWT-Token>
```

---

### 2. Authorization — **"What are you allowed to do?"**

After authentication, authorization determines whether the authenticated user has permission to access a resource.

For example:

```csharp
[Authorize]
[HttpGet]
public IActionResult GetProfile()
{
    return Ok();
}
```

Only authenticated users can access this endpoint.

For role-based authorization:

```csharp
[Authorize(Roles = "Admin")]
[HttpDelete("{id}")]
public IActionResult DeleteUser(int id)
{
    return Ok();
}
```

Only users with the **Admin** role can access it.

---

### Authentication vs Authorization

| Authentication         | Authorization                         |
| ---------------------- | ------------------------------------- |
| Identifies the user    | Checks permissions                    |
| **Who are you?**       | **What can you access?**              |
| Happens first          | Happens after authentication          |
| Login/token validation | Roles, policies, claims               |
| Example: JWT           | Example: `[Authorize(Roles="Admin")]` |

### ASP.NET Core Pipeline

```text
Request
   ↓
Authentication
   ↓
User Identity (Claims)
   ↓
Authorization
   ↓
Controller / Endpoint
```

**In short:** Authentication establishes **identity**, while Authorization controls **access**.
