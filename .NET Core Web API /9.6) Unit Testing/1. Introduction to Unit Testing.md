# Introduction to Unit Testing in ASP.NET Core

**Unit Testing** is the practice of testing the **smallest testable unit of code**, usually a method or class, in isolation to verify that it behaves as expected.

In ASP.NET Core Web API, unit tests are commonly written for:

* Controllers
* Services
* Repository methods
* Business logic
* MediatR handlers
* Validators

### 1. Why Unit Testing?

Suppose you have:

```csharp
public int Add(int a, int b)
{
    return a + b;
}
```

A unit test verifies that:

```text
Add(2, 3) → 5
```

If someone later changes the implementation and accidentally breaks it, the test will detect the problem.

### 2. Unit Test Structure

A common pattern is:

**Arrange → Act → Assert**

```csharp
[Fact]
public void Add_ShouldReturnCorrectSum()
{
    // Arrange
    var calculator = new Calculator();

    // Act
    var result = calculator.Add(2, 3);

    // Assert
    Assert.Equal(5, result);
}
```

| Step        | Purpose                                 |
| ----------- | --------------------------------------- |
| **Arrange** | Prepare objects, data, and dependencies |
| **Act**     | Execute the method being tested         |
| **Assert**  | Verify the expected result              |

### 3. Common Testing Frameworks in .NET

| Framework            | Purpose                       |
| -------------------- | ----------------------------- |
| **xUnit**            | Popular testing framework     |
| **NUnit**            | Alternative testing framework |
| **MSTest**           | Microsoft's testing framework |
| **Moq**              | Mocking dependencies          |
| **FluentAssertions** | More readable assertions      |

For your **1-year .NET developer** level, I would focus first on:

> **xUnit → Moq → Arrange/Act/Assert → Testing Services/Handlers → Exception & edge-case testing**

### 4. Unit Test vs Integration Test

**Unit Test**

```text
Controller/Service
      ↓
Mock dependency
      ↓
Test only the logic
```

Fast and isolated.

**Integration Test**

```text
API
 ↓
Service
 ↓
Database
```

Tests whether multiple components work together.

### 5. Example in ASP.NET Core

Suppose you have:

```csharp
public class DoctorService
{
    public bool IsApproved(Doctor doctor)
    {
        return doctor.ApprovalStatus == ApprovalStatus.Approved;
    }
}
```

The unit test could be:

```csharp
[Fact]
public void IsApproved_WhenDoctorIsApproved_ReturnsTrue()
{
    // Arrange
    var service = new DoctorService();

    var doctor = new Doctor
    {
        ApprovalStatus = ApprovalStatus.Approved
    };

    // Act
    var result = service.IsApproved(doctor);

    // Assert
    Assert.True(result);
}
```

The test doesn't need a database, API, or HTTP request. It tests **only the business logic**.

### 6. What You Should Learn

For your project, learn unit testing in this order:

```text
1. What is Unit Testing
        ↓
2. xUnit Basics
        ↓
3. [Fact] and [Theory]
        ↓
4. Arrange → Act → Assert
        ↓
5. Assertions
        ↓
6. Testing Exceptions
        ↓
7. Mocking with Moq
        ↓
8. Testing Services
        ↓
9. Testing MediatR Handlers
        ↓
10. Testing Controllers
        ↓
11. Testing Validators
        ↓
12. Code Coverage
```

**Key interview point:**

> A unit test should test one unit of behavior in isolation, with external dependencies such as databases, APIs, or services replaced by mocks or other test doubles.
