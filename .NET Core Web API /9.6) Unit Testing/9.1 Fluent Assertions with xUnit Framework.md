# Fluent Assertions with xUnit Framework in ASP.NET Core

**Fluent Assertions** is a .NET assertion library that makes test assertions **more readable and expressive**.

Instead of writing:

```csharp
Assert.Equal("Dr. John", result.Name);
```

you can write:

```csharp
result.Name.Should().Be("Dr. John");
```

It works very well with **xUnit**.

---

## 1. Install FluentAssertions

Add the NuGet package to your test project:

```bash
dotnet add package FluentAssertions
```

Then import:

```csharp
using FluentAssertions;
```

---

# 2. Basic Comparison

### xUnit

```csharp
Assert.Equal(10, result);
```

### Fluent Assertions

```csharp
result.Should().Be(10);
```

The second version reads almost like plain English:

> Result should be 10.

---

# 3. String Assertions

### xUnit

```csharp
Assert.Equal("John", doctor.Name);
```

### Fluent Assertions

```csharp
doctor.Name.Should().Be("John");
```

Other useful string assertions:

```csharp
doctor.Name.Should().NotBeNull();
doctor.Name.Should().NotBeEmpty();
doctor.Name.Should().Contain("John");
doctor.Name.Should().StartWith("Dr.");
doctor.Name.Should().EndWith("John");
```

---

# 4. Boolean Assertions

Instead of:

```csharp
Assert.True(doctor.IsApproved);
Assert.False(doctor.IsDeleted);
```

Use:

```csharp
doctor.IsApproved.Should().BeTrue();
doctor.IsDeleted.Should().BeFalse();
```

Very readable.

# 5. Null Assertions

### xUnit

```csharp
Assert.NotNull(result);
Assert.Null(result);
```

### Fluent Assertions

```csharp
result.Should().NotBeNull();
result.Should().BeNull();
```

# 6. Object Assertions

Suppose:

```csharp
var doctor = new Doctor
{
    Id = doctorId,
    Name = "Dr. John",
    Specialization = "Cardiology"
};
```

You can write:

```csharp
doctor.Should().NotBeNull();
doctor.Name.Should().Be("Dr. John");
doctor.Specialization.Should().Be("Cardiology");
```

You can also compare an entire object:

```csharp
doctor.Should().BeEquivalentTo(expectedDoctor);
```

This is particularly useful when testing API responses or DTOs.

# 7. Collection Assertions

Suppose:

```csharp
var doctors = await service.GetDoctorsAsync();
```

With xUnit:

```csharp
Assert.NotEmpty(doctors);
Assert.Equal(3, doctors.Count);
```

With Fluent Assertions:

```csharp
doctors.Should().NotBeEmpty();
doctors.Should().HaveCount(3);
```

You can also do:

```csharp
doctors.Should().Contain(doctor);
```

```csharp
doctors.Should().NotContain(deletedDoctor);
```

```csharp
doctors.Should().OnlyContain(x => x.IsApproved);
```

# 8. Real Service Test

Suppose we have:

```csharp
public async Task<Doctor?> GetDoctorAsync(Guid id)
{
    return await _repository.GetByIdAsync(id);
}
```

### Using xUnit

```csharp
[Fact]
public async Task GetDoctorAsync_WhenDoctorExists_ReturnsDoctor()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        Name = "Dr. John"
    };

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _service.GetDoctorAsync(doctorId);

    // Assert
    Assert.NotNull(result);
    Assert.Equal(doctorId, result.Id);
    Assert.Equal("Dr. John", result.Name);
}
```

### Using Fluent Assertions

```csharp
[Fact]
public async Task GetDoctorAsync_WhenDoctorExists_ReturnsDoctor()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        Name = "Dr. John"
    };

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _service.GetDoctorAsync(doctorId);

    // Assert
    result.Should().NotBeNull();
    result!.Id.Should().Be(doctorId);
    result.Name.Should().Be("Dr. John");
}
```

# 9. Exception Testing

This is one area where Fluent Assertions is particularly readable.

### xUnit

```csharp
await Assert.ThrowsAsync<ArgumentException>(
    () => service.GetDoctorAsync(Guid.Empty));
```

### Fluent Assertions

```csharp
Func<Task> action = () =>
    service.GetDoctorAsync(Guid.Empty);

await action.Should()
    .ThrowAsync<ArgumentException>();
```

You can also verify the message:

```csharp
await action.Should()
    .ThrowAsync<ArgumentException>()
    .WithMessage("Invalid doctor ID");
```

# 10. HTTP Response Assertions

Suppose an integration test returns:

```csharp
var response = await client.GetAsync("/api/doctors");
```

With xUnit:

```csharp
Assert.Equal(
    HttpStatusCode.OK,
    response.StatusCode);
```

With Fluent Assertions:

```csharp
response.StatusCode.Should()
    .Be(HttpStatusCode.OK);
```

You can then deserialize:

```csharp
var doctors =
    await response.Content
        .ReadFromJsonAsync<List<DoctorResponse>>();

doctors.Should().NotBeNull();
doctors.Should().NotBeEmpty();
```

# 11. Comparing Objects with `BeEquivalentTo`

This is one of the most useful Fluent Assertions features.

Suppose:

```csharp
var expected = new DoctorResponse
{
    Id = doctorId,
    Name = "Dr. John",
    Specialization = "Cardiology"
};
```

Instead of checking every property:

```csharp
Assert.Equal(expected.Id, result.Id);
Assert.Equal(expected.Name, result.Name);
Assert.Equal(expected.Specialization, result.Specialization);
```

You can write:

```csharp
result.Should().BeEquivalentTo(expected);
```

Fluent Assertions compares the object's properties for you.

# 12. Testing Collections

Suppose the API returns:

```text
Dr. John
Dr. Smith
Dr. David
```

You can write:

```csharp
doctors.Should().HaveCount(3);

doctors.Should().Contain(x =>
    x.Name == "Dr. John");

doctors.Should().OnlyContain(x =>
    x.IsApproved);
```

You can also verify ordering:

```csharp
doctors.Should()
    .BeInAscendingOrder(x => x.Name);
```

# 13. `[Theory]` + Fluent Assertions

They work together nicely.

```csharp
[Theory]
[InlineData(5, true)]
[InlineData(10, true)]
[InlineData(2, false)]
public void IsExperienced_ReturnsExpectedResult(
    int years,
    bool expected)
{
    var result = years >= 5;

    result.Should().Be(expected);
}
```

# 14. Why Use Fluent Assertions?

The main advantage is **readability**.

Compare:

```csharp
Assert.Equal("Cardiology", result.Specialization);
Assert.NotNull(result);
Assert.True(result.IsApproved);
Assert.Equal(3, doctors.Count);
```

with:

```csharp
result.Specialization.Should().Be("Cardiology");
result.Should().NotBeNull();
result.IsApproved.Should().BeTrue();
doctors.Should().HaveCount(3);
```

The second style reads more naturally.

It also provides more descriptive failure messages, which can make diagnosing failed tests easier.

# 15. Common Fluent Assertions

| Requirement        | Fluent Assertion             |
| ------------------ | ---------------------------- |
| Equal              | `.Should().Be()`             |
| Not equal          | `.Should().NotBe()`          |
| Null               | `.Should().BeNull()`         |
| Not null           | `.Should().NotBeNull()`      |
| True               | `.Should().BeTrue()`         |
| False              | `.Should().BeFalse()`        |
| Empty              | `.Should().BeEmpty()`        |
| Not empty          | `.Should().NotBeEmpty()`     |
| Count              | `.Should().HaveCount()`      |
| Contains           | `.Should().Contain()`        |
| Does not contain   | `.Should().NotContain()`     |
| Equivalent objects | `.Should().BeEquivalentTo()` |
| Exception          | `.Should().ThrowAsync<T>()`  |
| String contains    | `.Should().Contain()`        |
| Greater than       | `.Should().BeGreaterThan()`  |
| Less than          | `.Should().BeLessThan()`     |

# 16. xUnit + Fluent Assertions + Moq

These three tools have different responsibilities:

```text
xUnit
  ↓
Test Framework
  ↓
Runs the tests


Moq
  ↓
Mocking Framework
  ↓
Mocks dependencies


Fluent Assertions
  ↓
Assertion Library
  ↓
Checks expected results
```

Together:

```text
        xUnit
          ↓
      Runs Test
          ↓
         Moq
          ↓
   Mock Repository
          ↓
       Service
          ↓
 Fluent Assertions
          ↓
    Verify Result
```

## Interview Answer

**Q: What is Fluent Assertions?**

> Fluent Assertions is a .NET assertion library that provides a readable and expressive syntax for validating test results. It can be used with testing frameworks such as xUnit to assert values, objects, collections, exceptions, and HTTP responses.

**Q: Why use it instead of xUnit's Assert?**

> Fluent Assertions provides a more readable assertion syntax and richer failure messages, especially when comparing complex objects and collections.
