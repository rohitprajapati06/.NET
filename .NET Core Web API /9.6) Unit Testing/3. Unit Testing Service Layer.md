# Unit Testing Service Layer in ASP.NET Core Web API

The **Service Layer** contains the application's **business logic**, so it is one of the most important layers to unit test.

For your level, focus on testing:

* Business rules
* Success scenarios
* Failure scenarios
* Exceptions
* Dependency interactions

We'll use **xUnit + Moq**.

---

## 1. Typical Architecture

```text
Controller
    ↓
Service
    ↓
Repository
    ↓
Database
```

During a **unit test**, we don't use the real database.

```text
        ┌─────────────────┐
        │  DoctorService  │
        └────────┬────────┘
                 ↓
        Mock<IDoctorRepository>
                 ↓
             Fake Data
```

We test only the `DoctorService`.

---

# 2. Service Example

Suppose we have:

```csharp
public class DoctorService
{
    private readonly IDoctorRepository _repository;

    public DoctorService(IDoctorRepository repository)
    {
        _repository = repository;
    }

    public async Task<Doctor?> GetDoctorByIdAsync(Guid id)
    {
        return await _repository.GetByIdAsync(id);
    }
}
```

Repository:

```csharp
public interface IDoctorRepository
{
    Task<Doctor?> GetByIdAsync(Guid id);
}
```

---

# 3. Create the Test Class

```csharp
public class DoctorServiceTests
{
    private readonly Mock<IDoctorRepository> _repositoryMock;
    private readonly DoctorService _service;

    public DoctorServiceTests()
    {
        _repositoryMock = new Mock<IDoctorRepository>();

        _service = new DoctorService(
            _repositoryMock.Object);
    }
}
```

Here:

```text
Mock<IDoctorRepository>
          ↓
DoctorService
```

The service receives the **mock repository instead of the real repository**.

---

# 4. Test Successful Scenario

```csharp
[Fact]
public async Task GetDoctorByIdAsync_WhenDoctorExists_ReturnsDoctor()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        Name = "Dr. John",
        Specialization = "Cardiology"
    };

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _service.GetDoctorByIdAsync(doctorId);

    // Assert
    Assert.NotNull(result);
    Assert.Equal(doctorId, result.Id);
    Assert.Equal("Dr. John", result.Name);
}
```

### What happens?

**Arrange**

```csharp
_repositoryMock
    .Setup(x => x.GetByIdAsync(doctorId))
    .ReturnsAsync(doctor);
```

We're telling Moq:

> When the service asks the repository for this doctor, return our fake doctor.

**Act**

```csharp
var result = await _service.GetDoctorByIdAsync(doctorId);
```

**Assert**

```csharp
Assert.NotNull(result);
Assert.Equal(doctorId, result.Id);
```

# 5. Test Doctor Not Found

A good service test should also cover failure/edge cases.

```csharp
[Fact]
public async Task GetDoctorByIdAsync_WhenDoctorDoesNotExist_ReturnsNull()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync((Doctor?)null);

    // Act
    var result = await _service.GetDoctorByIdAsync(doctorId);

    // Assert
    Assert.Null(result);
}
```

Now we have:

| Scenario             | Expected        |
| -------------------- | --------------- |
| Doctor exists        | Doctor returned |
| Doctor doesn't exist | `null`          |

# 6. Testing Business Logic

This is where service-layer testing becomes particularly useful.

Suppose our service contains:

```csharp
public async Task<bool> ApproveDoctorAsync(Guid id)
{
    var doctor = await _repository.GetByIdAsync(id);

    if (doctor == null)
        return false;

    doctor.IsApproved = true;

    await _repository.UpdateAsync(doctor);

    return true;
}
```

We can test the business rule.

### Test

```csharp
[Fact]
public async Task ApproveDoctorAsync_WhenDoctorExists_ApprovesDoctor()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        IsApproved = false
    };

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _service.ApproveDoctorAsync(doctorId);

    // Assert
    Assert.True(result);
    Assert.True(doctor.IsApproved);
}
```

---

# 7. Verify Repository Was Called

Moq's `Verify()` is very important.

```csharp
_repositoryMock.Verify(
    x => x.GetByIdAsync(doctorId),
    Times.Once);
```

This verifies:

> `GetByIdAsync()` was called exactly once.

For the approval example:

```csharp
_repositoryMock.Verify(
    x => x.UpdateAsync(doctor),
    Times.Once);
```

So we're testing not only **what the service returned**, but also **how it interacted with its dependency**.

# 8. Testing Exceptions

Suppose the service does this:

```csharp
public async Task<Doctor?> GetDoctorByIdAsync(Guid id)
{
    if (id == Guid.Empty)
        throw new ArgumentException("Invalid doctor ID");

    return await _repository.GetByIdAsync(id);
}
```

Test it:

```csharp
[Fact]
public async Task GetDoctorByIdAsync_WhenIdIsEmpty_ThrowsException()
{
    // Arrange
    var id = Guid.Empty;

    // Act & Assert
    await Assert.ThrowsAsync<ArgumentException>(
        () => _service.GetDoctorByIdAsync(id));
}
```

This verifies the service's validation/business rule.

# 9. Service Testing Flow

For a real project, think like this:

```text
                 UNIT TEST
                     │
                     ▼
             ┌───────────────┐
             │    Service    │
             └───────┬───────┘
                     │
              ┌──────▼──────┐
              │     Mock    │
              │ Repository  │
              └─────────────┘
```

You control the repository's response:

```text
Repository → Doctor
Repository → null
Repository → Exception
```

Then verify how the service behaves.

---

# 10. What Should We Test in a Service?

For each service method, normally cover:

| Test                   | Example                         |
| ---------------------- | ------------------------------- |
| Success                | Doctor exists                   |
| Not found              | Doctor doesn't exist            |
| Validation             | Empty/invalid ID                |
| Business rule          | Doctor cannot be approved twice |
| Exception              | Repository throws exception     |
| Dependency interaction | Repository called once          |
| Data modification      | Doctor status changed           |

## Key Interview Answer

If an interviewer asks **"How do you unit test the service layer?"**, a good answer is:

> "I isolate the service from its external dependencies such as repositories or other services by mocking them using Moq. I arrange the required test data and mock behavior, call the service method, and assert the expected result and business behavior. I also use `Verify()` to ensure dependencies were called correctly and cover success, failure, validation, and exception scenarios."
