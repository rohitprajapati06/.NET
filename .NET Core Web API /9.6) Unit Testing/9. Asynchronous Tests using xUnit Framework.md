# Asynchronous Tests using xUnit Framework in ASP.NET Core

In ASP.NET Core, most real application code is **asynchronous** because it commonly performs:

* Database operations with EF Core
* HTTP calls
* File operations
* Service/repository calls
* MediatR handlers

For these methods, xUnit tests should also use **`async` / `await`**.

---

## 1. Synchronous Test

Suppose we have:

```csharp
public int Add(int a, int b)
{
    return a + b;
}
```

Test:

```csharp
[Fact]
public void Add_ReturnsCorrectResult()
{
    // Arrange
    var calculator = new Calculator();

    // Act
    var result = calculator.Add(2, 3);

    // Assert
    Assert.Equal(5, result);
}
```

This is synchronous because the method doesn't return a `Task`.

---

# 2. Asynchronous Method

Now suppose our service accesses a database:

```csharp
public async Task<Doctor?> GetDoctorAsync(Guid id)
{
    return await _repository.GetByIdAsync(id);
}
```

The return type is:

```text
Task<Doctor?>
```

Therefore, the test should also be asynchronous.

---

# 3. Basic Async xUnit Test

```csharp
[Fact]
public async Task GetDoctorAsync_WhenDoctorExists_ReturnsDoctor()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        Name = "Dr. John"
    };

    _repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _service.GetDoctorAsync(doctorId);

    // Assert
    Assert.NotNull(result);
    Assert.Equal(doctorId, result.Id);
}
```

Notice:

```csharp
public async Task ...
```

and:

```csharp
await _service.GetDoctorAsync(doctorId);
```

---

# 4. Why `Task` Instead of `void`?

For asynchronous tests, use:

```csharp
public async Task TestMethod()
```

Not:

```csharp
public async void TestMethod()
```

### Correct

```csharp
[Fact]
public async Task GetDoctor_ReturnsDoctor()
{
    var result = await service.GetDoctorAsync(id);

    Assert.NotNull(result);
}
```

### Avoid

```csharp
[Fact]
public async void GetDoctor_ReturnsDoctor()
{
    ...
}
```

`async void` doesn't allow the test framework to properly await the test operation and handle exceptions reliably.

---

# 5. Async Test with `ReturnsAsync()`

Moq provides:

```csharp
ReturnsAsync()
```

For example:

```csharp
_repositoryMock
    .Setup(x => x.GetByIdAsync(doctorId))
    .ReturnsAsync(doctor);
```

The repository method returns:

```csharp
Task<Doctor?>
```

so `ReturnsAsync()` supplies the asynchronous result.

Conceptually:

```text
Repository
    ↓
Task<Doctor>
    ↓
await
    ↓
Doctor
```

# 6. Async Test When Data Doesn't Exist

```csharp
[Fact]
public async Task GetDoctorAsync_WhenDoctorDoesNotExist_ReturnsNull()

    // Arrange
    var doctorId = Guid.NewGuid();

    // Act
    var result = await _service.GetDoctorAsync(doctorId);

    // Assert

}
```

# 7. Testing Async Exceptions

Suppose:

```csharp
public async Task<Doctor> GetDoctorAsync(Guid id)
{
    if (id == Guid.Empty)
        throw new ArgumentException("Invalid ID");

    return await _repository.GetByIdAsync(id);
}
```

Test:

```csharp
[Fact]
public async Task GetDoctorAsync_WhenIdIsEmpty_ThrowsException()
{
    // Act & Assert
    await Assert.ThrowsAsync<ArgumentException>(
        () => _service.GetDoctorAsync(Guid.Empty));
}
```

The important part is:

```csharp
await Assert.ThrowsAsync<ArgumentException>(...)
```

Because the exception occurs during an asynchronous operation.

# 8. Async Controller Test

Your controllers are also commonly asynchronous.

Controller:

```csharp
[HttpGet("{id}")]
public async Task<IActionResult> GetDoctor(Guid id)
{
    var doctor = await _service.GetDoctorAsync(id);

    if (doctor == null)
        return NotFound();

    return Ok(doctor);
}
```

Test:

```csharp
[Fact]
public async Task GetDoctor_WhenDoctorExists_ReturnsOk()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var doctor = new Doctor
    {
        Id = doctorId,
        Name = "Dr. John"
    };

    _serviceMock
        .Setup(x => x.GetDoctorAsync(doctorId))
        .ReturnsAsync(doctor);

    // Act
    var result = await _controller.GetDoctor(doctorId);

    // Assert
    var okResult = Assert.IsType<OkObjectResult>(result);

    Assert.Equal(doctor, okResult.Value);
}
```

# 9. Async Repository Test

Suppose:

```csharp
public async Task<List<Doctor>> GetAllAsync()
{
    return await _context.Doctors.ToListAsync();
}
```

Test:

```csharp
[Fact]
public async Task GetAllAsync_ReturnsDoctors()
{
    // Arrange
    using var context = CreateContext();

    context.Doctors.AddRange(
        new Doctor
        {
            Id = Guid.NewGuid(),
            Name = "Dr. John"
        },
        new Doctor
        {
            Id = Guid.NewGuid(),
            Name = "Dr. Smith"
        });

    await context.SaveChangesAsync();

    var repository = new DoctorRepository(context);

    // Act
    var result = await repository.GetAllAsync();

    // Assert
    Assert.Equal(2, result.Count);
}
```

Notice that both database operations are awaited:

```csharp
await context.SaveChangesAsync();
```

and:

```csharp
await repository.GetAllAsync();
```

# 10. Async `[Theory]`

You can combine asynchronous tests with `[Theory]`.

```csharp
[Theory]
[InlineData(5, true)]
[InlineData(10, true)]
[InlineData(2, false)]
public async Task IsExperienced_ReturnsExpectedResult(
    int experience,
    bool expected)
{
    // Act
    var result = await _service.IsExperiencedAsync(experience);

    // Assert
    Assert.Equal(expected, result);
}
```

So `[Theory]` and `async` work together normally.

# 11. Common Mistake: Forgetting `await`

Incorrect:

```csharp
var result = _service.GetDoctorAsync(doctorId);

Assert.NotNull(result);
```

Here:

```text
result = Task<Doctor>
```

not:

```text
result = Doctor
```

Correct:

```csharp
var result = await _service.GetDoctorAsync(doctorId);

Assert.NotNull(result);
```

Now:

```text
await Task<Doctor>
        ↓
     Doctor
```

---

# 12. Common Mistake: Using `.Result`

Avoid:

```csharp
var result = _service.GetDoctorAsync(id).Result;
```

Prefer:

```csharp
var result = await _service.GetDoctorAsync(id);
```

Using `.Result` or `.Wait()` can cause blocking and, in some environments, deadlock-related problems.

The general rule is:

> **If the application method is asynchronous, make the test asynchronous and use `await`.**

---

# 13. Async Testing Flow

For your ASP.NET Core project:

```text
Test
 ↓
await Controller
 ↓
await Service
 ↓
await Repository
 ↓
await EF Core
 ↓
Result
 ↓
Assert
```

Example:

```csharp
[Fact]
public async Task CancelAppointment_WhenValid_CancelsAppointment()
{
    // Arrange
    ...

    // Act
    var result = await _handler.Handle(command, CancellationToken.None);

    // Assert
    Assert.True(result);
}
```

This pattern is especially relevant to your **MediatR handlers**, because methods such as:

```csharp
Handle(...)
```

are normally asynchronous.

## Interview Questions

### What is an asynchronous unit test?

> An asynchronous unit test tests a method that returns a `Task` or `Task<T>`. In xUnit, the test method is declared with `async Task`, and the asynchronous operation is awaited.

### Why shouldn't we use `async void`?

> Because the test framework cannot properly await an `async void` test or reliably observe exceptions from it. `async Task` allows xUnit to track completion and exceptions correctly.

### Why use `await` instead of `.Result`?

> `await` is non-blocking and correctly unwraps the asynchronous result, while `.Result` blocks the calling thread and can cause deadlock or blocking issues.

### Key pattern to remember

```text
Synchronous
────────────
[Fact]
public void Test()
{
    ...
}


Asynchronous
────────────
[Fact]
public async Task Test()
{
    var result = await SomeMethodAsync();

    Assert...
}
```
