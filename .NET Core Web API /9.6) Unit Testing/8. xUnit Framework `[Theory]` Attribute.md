# xUnit Framework `[Theory]` Attribute in ASP.NET Core

The **`[Theory]`** attribute in xUnit is used when you want to run **the same test with multiple sets of input data**.

It is useful when the test logic remains the same but the input values change.

---

## 1. `[Fact]` vs `[Theory]`

| `[Fact]`                 | `[Theory]`                     |
| ------------------------ | ------------------------------ |
| Tests one fixed scenario | Tests multiple input scenarios |
| No parameters            | Supports parameters            |
| Same input every time    | Different inputs               |
| Simple test cases        | Data-driven tests              |

### `[Fact]`

```csharp
[Fact]
public void Add_TwoNumbers_ReturnsSum()
{
    var result = Add(2, 3);

    Assert.Equal(5, result);
}
```

### `[Theory]`

```csharp
[Theory]
[InlineData(2, 3, 5)]
[InlineData(5, 5, 10)]
[InlineData(10, 20, 30)]
public void Add_TwoNumbers_ReturnsSum(
    int a,
    int b,
    int expected)
{
    var result = Add(a, b);

    Assert.Equal(expected, result);
}
```

The same test runs **three times**:

```text
2 + 3   → 5
5 + 5   → 10
10 + 20 → 30
```

---

# 2. `[InlineData]`

The most common way to provide data to a `[Theory]` is `[InlineData]`.

```csharp
[Theory]
[InlineData(10, 20)]
[InlineData(50, 100)]
[InlineData(100, 200)]
public void TestAddition(int a, int expected)
{
    var result = a + a;

    Assert.Equal(expected, result);
}
```

Each `[InlineData]` creates a separate test case.

```text
Theory
 ├── Test Case 1 → 10 → 20
 ├── Test Case 2 → 50 → 100
 └── Test Case 3 → 100 → 200
```

# 3. Real ASP.NET Core Example

Suppose your service validates a doctor's experience:

```csharp
public bool IsExperienced(int experienceYears)
{
    return experienceYears >= 5;
}
```

Instead of writing multiple `[Fact]` tests:

```csharp
[Fact]
public void IsExperienced_5Years_ReturnsTrue()
{
    ...
}

[Fact]
public void IsExperienced_10Years_ReturnsTrue()
{
    ...
}
```

Use `[Theory]`:

```csharp
[Theory]
[InlineData(5)]
[InlineData(10)]
[InlineData(15)]
public void IsExperienced_WhenExperienceIsFiveOrMore_ReturnsTrue(
    int experienceYears)
{
    var service = new DoctorService();

    var result = service.IsExperienced(experienceYears);

    Assert.True(result);
}
```

# 4. Testing Multiple Scenarios

You can also test both valid and invalid values.

```csharp
[Theory]
[InlineData(0, false)]
[InlineData(2, false)]
[InlineData(4, false)]
[InlineData(5, true)]
[InlineData(10, true)]
public void IsExperienced_ReturnsExpectedResult(
    int experienceYears,
    bool expected)
{
    var service = new DoctorService();

    var result = service.IsExperienced(experienceYears);

    Assert.Equal(expected, result);
}
```

This is a very good use of `[Theory]`.

| Experience | Expected |
| ---------: | -------- |
|          0 | `false`  |
|          2 | `false`  |
|          4 | `false`  |
|          5 | `true`   |
|         10 | `true`   |

# 5. `[Theory]` with Strings

```csharp
[Theory]
[InlineData("Cardiology", true)]
[InlineData("Neurology", true)]
[InlineData("", false)]
public void ValidateSpecialization(
    string specialization,
    bool expected)
{
    var result = !string.IsNullOrWhiteSpace(specialization);

    Assert.Equal(expected, result);
}
```

---

# 6. `[Theory]` with Multiple Parameters

You can provide multiple parameters:

```csharp
[Theory]
[InlineData(100, 10, 110)]
[InlineData(200, 20, 220)]
[InlineData(500, 50, 550)]
public void CalculateAmount(
    decimal amount,
    decimal tax,
    decimal expected)
{
    var result = amount + tax;

    Assert.Equal(expected, result);
}
```

Each row represents one test case.

---

# 7. `[Theory]` with Boolean Values

Very common for testing business rules:

```csharp
[Theory]
[InlineData(true, true)]
[InlineData(false, false)]
public void DoctorApproval_ReturnsExpectedResult(
    bool isApproved,
    bool expected)
{
    var result = isApproved;

    Assert.Equal(expected, result);
}
```

# 8. `[Theory]` vs Multiple `[Fact]`

### Without Theory

```csharp
[Fact]
public void ValidateAge_18_ReturnsTrue()
{
    ...
}

[Fact]
public void ValidateAge_25_ReturnsTrue()
{
    ...
}

[Fact]
public void ValidateAge_10_ReturnsFalse()
{
    ...
}
```

### With Theory

```csharp
[Theory]
[InlineData(18, true)]
[InlineData(25, true)]
[InlineData(10, false)]
public void ValidateAge_ReturnsExpectedResult(
    int age,
    bool expected)
{
    ...
}
```

The `[Theory]` version is generally cleaner because the **test logic is identical**.

---

# 9. When Should You Use `[Fact]`?

Use `[Fact]` when there is **one fixed scenario**.

For example:

```csharp
[Fact]
public async Task GetDoctor_WhenDoctorDoesNotExist_ReturnsNull()
{
    ...
}
```

There may be no meaningful input variation.

---

# 10. When Should You Use `[Theory]`?

Use `[Theory]` when:

> **The same behavior needs to be tested with different inputs.**

Examples:

```text
Different ages
Different prices
Different statuses
Different IDs
Different validation inputs
Different appointment states
Different doctor experience values
```

# 11. Advanced `[Theory]` Data Sources

`[InlineData]` is not the only option.

xUnit also provides data attributes such as:

### `[MemberData]`

Useful when the test data is stored in a property/method.

```csharp
[Theory]
[MemberData(nameof(GetDoctorData))]
public void TestDoctor(
    string name,
    bool expected)
{
    ...
}

public static IEnumerable<object[]> GetDoctorData()
{
    yield return new object[] { "John", true };
    yield return new object[] { "Smith", true };
}
```

### `[ClassData]`

Useful when test data is placed in a separate class.

```csharp
[Theory]
[ClassData(typeof(DoctorTestData))]
public void TestDoctor(
    string name,
    bool expected)
{
    ...
}
```

For your current level, learn these in this order:

```text
[Fact]
   ↓
[Theory]
   ↓
[InlineData]
   ↓
[MemberData]
   ↓
[ClassData]
```

---

# 12. Important Point

`[Theory]` itself **doesn't provide the data**.

It tells xUnit:

> "This test should be executed using supplied test data."

The data comes from:

```text
[InlineData]
[MemberData]
[ClassData]
```

So:

```csharp
[Theory]
[InlineData(5, true)]
[InlineData(10, true)]
```

means:

```text
Theory
  ↓
Data Provider
  ↓
5, true
10, true
  ↓
Run test twice
```

## Interview Answer

**Q: What is `[Theory]` in xUnit?**

> `[Theory]` is used for data-driven testing in xUnit. It allows the same test method to execute multiple times with different input values. Test data can be supplied using attributes such as `[InlineData]`, `[MemberData]`, or `[ClassData]`.

**Q: Difference between `[Fact]` and `[Theory]`?**

> `[Fact]` is used for a single fixed test scenario, whereas `[Theory]` is used when the same test logic needs to be executed with multiple sets of input data.

### Remember

```text
[Fact]
   → One fixed scenario

[Theory]
   → Multiple input scenarios

[InlineData]
   → Supplies the inputs
```

For your SmartHealthcare project, `[Theory]` is particularly useful for testing **appointment status rules, doctor approval states, validation rules, and different input combinations**.
