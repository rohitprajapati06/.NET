# Real-Time ASP.NET Core Project Development for Unit Testing

Instead of learning unit testing only with `Calculator` examples, let's build it around a **real ASP.NET Core Web API project** similar to your SmartHealthcare project.

We'll use **xUnit + Moq** and gradually test real application code.

# 4. Create a Repository Interface

In a real project, the service shouldn't directly depend on the database.

```csharp
public interface IDoctorRepository
{
    Task<Doctor?> GetByIdAsync(Guid id);

    Task<List<Doctor>> GetAllAsync();
}
```

This is important for unit testing because we can **mock** the repository.

---

# 5. Create the Service

```csharp
public class DoctorService
{
    private readonly IDoctorRepository _repository;

    public DoctorService(IDoctorRepository repository)
    {
        _repository = repository;
    }

    public async Task<Doctor?> GetDoctorAsync(Guid id)
    {
        return await _repository.GetByIdAsync(id);
    }
}
```

Our dependency is:

```text
DoctorService
      ↓
IDoctorRepository
      ↓
Database
```

During unit testing, we don't want the real database.

So we'll replace it with:

```text
DoctorService
      ↓
Mock<IDoctorRepository>
```

# 7. Write Our First Real Unit Test

Create:

```text
DoctorServiceTests.cs
```

```csharp
public class DoctorServiceTests
{
    [Fact]
    public async Task GetDoctorAsync_WhenDoctorExists_ReturnsDoctor()
    {
        // Arrange
        var doctorId = Guid.NewGuid();

        var doctor = new Doctor
        {
            Id = doctorId,
            Name = "Dr. John",
            Specialization = "Cardiology",
            IsApproved = true
        };

        var repositoryMock = new Mock<IDoctorRepository>();

        repositoryMock
            .Setup(x => x.GetByIdAsync(doctorId))
            .ReturnsAsync(doctor);

        var service = new DoctorService(repositoryMock.Object);

        // Act
        var result = await service.GetDoctorAsync(doctorId);

        // Assert
        Assert.NotNull(result);
        Assert.Equal(doctorId, result.Id);
        Assert.Equal("Dr. John", result.Name);
    }
}
```

---

# 8. Understand What Just Happened

This is the most important part for you as a beginner.

### Arrange

We prepare the test:

```csharp
var doctorId = Guid.NewGuid();
```

Create fake doctor data:

```csharp
var doctor = new Doctor
{
    Id = doctorId,
    Name = "Dr. John"
};
```

Create a mock repository:

```csharp
var repositoryMock = new Mock<IDoctorRepository>();
```

Tell the mock what to return:

```csharp
repositoryMock
    .Setup(x => x.GetByIdAsync(doctorId))
    .ReturnsAsync(doctor);
```

Meaning:

> "Whenever `GetByIdAsync(doctorId)` is called, return this doctor."

---

### Act

Call the actual method we're testing:

```csharp
var result = await service.GetDoctorAsync(doctorId);
```

---

### Assert

Verify the result:

```csharp
Assert.NotNull(result);
Assert.Equal(doctorId, result.Id);
Assert.Equal("Dr. John", result.Name);
```

So:

```text
Arrange
   ↓
Create mock + test data
   ↓
Act
   ↓
Call actual service
   ↓
Assert
   ↓
Verify expected result
```

---

# 9. Why Didn't We Use a Real Database?

Because this is a **unit test**.

We only want to test:

```text
DoctorService.GetDoctorAsync()
```

We don't want to test:

* SQL Server
* Entity Framework Core
* Network
* Database connection
* Repository implementation

Those would belong to integration testing.

---

# 10. Test a Negative Scenario

Real applications need to test failure/edge cases too.

Suppose the doctor doesn't exist.

```csharp
[Fact]
public async Task GetDoctorAsync_WhenDoctorDoesNotExist_ReturnsNull()
{
    // Arrange
    var doctorId = Guid.NewGuid();

    var repositoryMock = new Mock<IDoctorRepository>();

    repositoryMock
        .Setup(x => x.GetByIdAsync(doctorId))
        .ReturnsAsync((Doctor?)null);

    var service = new DoctorService(repositoryMock.Object);

    // Act
    var result = await service.GetDoctorAsync(doctorId);

    // Assert
    Assert.Null(result);
}
```

Now we're testing:

```text
Doctor exists     → Doctor returned
Doctor not found  → null returned
```

> **Unit testing means isolating one piece of application logic, controlling its dependencies, executing it, and verifying the expected behavior.**
