# FluentValidation Custom Validators in ASP.NET Core Web API

**Custom Validators** are used when FluentValidation's built-in rules like `NotEmpty()`, `EmailAddress()`, or `GreaterThan()` are not sufficient for your business requirement.

There are two common approaches:

### 1. Using `Must()`

For simple custom validation logic:

```csharp
public class EmployeeValidator : AbstractValidator<Employee>
{
    public EmployeeValidator()
    {
        RuleFor(x => x.Name)
            .Must(name => name.All(char.IsLetter))
            .WithMessage("Name must contain only letters.");
    }
}
```

Here, `Must()` accepts a custom function that returns `true` or `false`.

---

### 2. Creating a Reusable Custom Validator

Suppose we want to validate a **strong password**.

```csharp
public class StrongPasswordValidator<T> : PropertyValidator<T, string>
{
    public override string Name => "StrongPasswordValidator";

    public override bool IsValid(
        ValidationContext<T> context,
        string value)
    {
        return !string.IsNullOrEmpty(value)
            && value.Any(char.IsUpper)
            && value.Any(char.IsLower)
            && value.Any(char.IsDigit);
    }

    protected override string GetDefaultMessageTemplate(
        string errorCode)
    {
        return "{PropertyName} must contain uppercase, lowercase, and numeric characters.";
    }
}
```

Then use it:

```csharp
public class EmployeeValidator : AbstractValidator<Employee>
{
    public EmployeeValidator()
    {
        RuleFor(x => x.Password)
            .SetValidator(new StrongPasswordValidator<Employee>());
    }
}
```

### When to use which?

| Approach                   | Use when                                       |
| -------------------------- | ---------------------------------------------- |
| `Must()`                   | Small, one-off custom rule                     |
| Custom `PropertyValidator` | Complex or reusable validation logic           |
| `MustAsync()`              | Custom validation requiring DB/API async calls |

**Key point:** Custom validators allow you to move **business-specific validation rules** out of your DTO/model and keep them reusable and testable.
