# Validate Nested Complex or Collection Properties using FluentValidation

When a model contains **nested objects or collections**, FluentValidation allows you to create separate validators and connect them using `SetValidator()`.

### 1. Nested Complex Property

Suppose we have:

```csharp
public class Employee
{
    public string Name { get; set; }
    public Address Address { get; set; }
}

public class Address
{
    public string City { get; set; }
    public string ZipCode { get; set; }
}
```

Create a validator for `Address`:

```csharp
public class AddressValidator : AbstractValidator<Address>
{
    public AddressValidator()
    {
        RuleFor(x => x.City)
            .NotEmpty();

        RuleFor(x => x.ZipCode)
            .NotEmpty()
            .Length(6);
    }
}
```

Then use it inside `EmployeeValidator`:

```csharp
public class EmployeeValidator : AbstractValidator<Employee>
{
    public EmployeeValidator()
    {
        RuleFor(x => x.Name)
            .NotEmpty();

        RuleFor(x => x.Address)
            .SetValidator(new AddressValidator());
    }
}
```

So when `Employee` is validated, **AddressValidator is automatically executed**.

---

### 2. Validate Collection Properties

Consider:

```csharp
public class Order
{
    public List<OrderItem> Items { get; set; }
}

public class OrderItem
{
    public string ProductName { get; set; }
    public decimal Price { get; set; }
}
```

Create:

```csharp
public class OrderItemValidator : AbstractValidator<OrderItem>
{
    public OrderItemValidator()
    {
        RuleFor(x => x.ProductName)
            .NotEmpty();

        RuleFor(x => x.Price)
            .GreaterThan(0);
    }
}
```

Apply it to every collection item:

```csharp
public class OrderValidator : AbstractValidator<Order>
{
    public OrderValidator()
    {
        RuleForEach(x => x.Items)
            .SetValidator(new OrderItemValidator());
    }
}
```

`RuleForEach()` applies `OrderItemValidator` **to every item in the collection**.

### Summary

| Requirement                | FluentValidation                   |
| -------------------------- | ---------------------------------- |
| Nested object              | `SetValidator()`                   |
| Collection items           | `RuleForEach()` + `SetValidator()` |
| Simple collection rule     | `RuleForEach()`                    |
| Reusable nested validation | Separate `AbstractValidator<T>`    |

**Key point:** For enterprise applications, keeping **separate validators for nested DTOs** and composing them with `SetValidator()` makes validation clean, reusable, and maintainable.
