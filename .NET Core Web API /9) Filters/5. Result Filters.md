# Result Filters in ASP.NET Core Web API

**Result Filters** execute **before and after an action result is executed**. They are mainly used when you want to modify or customize the **HTTP response/result**.

### Interfaces

* `IResultFilter` → Synchronous
* `IAsyncResultFilter` → Asynchronous

### Example

```csharp id="rsl42"
public class CustomResultFilter : IResultFilter
{
    public void OnResultExecuting(ResultExecutingContext context)
    {
        Console.WriteLine("Before Result Execution");
    }

    public void OnResultExecuted(ResultExecutedContext context)
    {
        Console.WriteLine("After Result Execution");
    }
}
```

Register:

```csharp id="xk71pq"
builder.Services.AddScoped<CustomResultFilter>();
```

Apply it:

```csharp id="n4j8ws"
[ServiceFilter(typeof(CustomResultFilter))]
[HttpGet]
public IActionResult Get()
{
    return Ok(new { Message = "Success" });
}
```

### Execution Flow

```text
Controller Action
       ↓
Result Filter → Before
       ↓
Action Result Executes
       ↓
Result Filter → After
       ↓
HTTP Response
```

### Common Uses

* Add/modify **response headers**
* Customize response data
* Logging response information
* Measure result execution time
* Apply common response formatting

**Interview point:** Result Filters run **after the action has executed but before/after the action result is executed**, making them suitable for **response-related processing**.
