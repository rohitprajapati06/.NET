# Action Filters in ASP.NET Core Web API

**Action Filters** allow you to execute custom logic **before and after a controller action executes**.

They are commonly used for **logging, validation, performance measurement, and modifying action arguments/results**.

### Interfaces

* `IActionFilter` → Synchronous
* `IAsyncActionFilter` → Asynchronous

### Example

```csharp
public class LoggingFilter : IActionFilter
{
    public void OnActionExecuting(ActionExecutingContext context)
    {
        Console.WriteLine("Before Action");
    }

    public void OnActionExecuted(ActionExecutedContext context)
    {
        Console.WriteLine("After Action");
    }
}
```

Register:

```csharp
builder.Services.AddScoped<LoggingFilter>();
```

Apply to an action:

```csharp
[ServiceFilter(typeof(LoggingFilter))]
[HttpGet]
public IActionResult Get()
{
    return Ok("Data");
}
```

### Execution Flow

```text
Request
   ↓
Authorization Filter
   ↓
Resource Filter
   ↓
Action Filter → Before
   ↓
Controller Action
   ↓
Action Filter → After
   ↓
Result Filters
   ↓
Response
```

### Key Points

* Executes **around the controller action**.
* `OnActionExecuting()` → runs **before** the action.
* `OnActionExecuted()` → runs **after** the action.
* Can **short-circuit** execution by setting `context.Result`.
* Useful for **logging, validation, auditing, and performance tracking**.

**Interview point:** Action filters are specifically designed to execute logic **before and after an MVC controller action**.
