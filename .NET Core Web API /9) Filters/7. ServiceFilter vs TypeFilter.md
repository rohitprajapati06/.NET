# ServiceFilter vs TypeFilter in ASP.NET Core Web API

Both **`ServiceFilter`** and **`TypeFilter`** are used to apply filters that have **dependencies injected through Dependency Injection (DI)**.

### Comparison

| Feature                 | `ServiceFilter`                     | `TypeFilter`                                               |
| ----------------------- | ----------------------------------- | ---------------------------------------------------------- |
| Gets filter from        | **DI Container**                    | Creates filter using **DI**                                |
| Registration required   | **Yes**                             | **No**                                                     |
| Dependencies            | Resolved from DI                    | Resolved from DI                                           |
| Uses `IServiceProvider` | Yes                                 | Yes, internally                                            |
| Best suited for         | Filters already registered in DI    | Filters needing dependencies without explicit registration |
| Example                 | `[ServiceFilter(typeof(MyFilter))]` | `[TypeFilter(typeof(MyFilter))]`                           |

### ServiceFilter

First register the filter:

```csharp
builder.Services.AddScoped<MyFilter>();
```

Then:

```csharp
[ServiceFilter(typeof(MyFilter))]
public IActionResult Get()
{
    return Ok();
}
```

The filter instance is obtained directly from the **DI container**.

### TypeFilter

No separate filter registration is normally required:

```csharp
[TypeFilter(typeof(MyFilter))]
public IActionResult Get()
{
    return Ok();
}
```

ASP.NET Core creates the filter and resolves its constructor dependencies through **DI**.

### Simple Rule

```text
ServiceFilter → "Get this filter from DI"

TypeFilter    → "Create this filter using DI"
```

**Interview point:** Prefer `TypeFilter` when the filter itself doesn't need to be explicitly registered in DI. Use `ServiceFilter` when the filter is already registered and you want to resolve that registered service.
