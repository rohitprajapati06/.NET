# Resource Filters in ASP.NET Core Web API

**Resource Filters** execute **before and after the rest of the filter pipeline**. They are useful when you need to perform logic **very early in request processing**, especially for **caching or short-circuiting requests**.

They implement either:

* `IResourceFilter` → Synchronous
* `IAsyncResourceFilter` → Asynchronous

### Example

```csharp
public class MyResourceFilter : IResourceFilter
{
    public void OnResourceExecuting(ResourceExecutingContext context)
    {
        Console.WriteLine("Before resource execution");
    }

    public void OnResourceExecuted(ResourceExecutedContext context)
    {
        Console.WriteLine("After resource execution");
    }
}
```

Register:

```csharp
builder.Services.AddScoped<MyResourceFilter>();
```

Apply it:

```csharp
[ServiceFilter(typeof(MyResourceFilter))]
public IActionResult Get()
{
    return Ok("Data");
}
```

### Execution Flow

```text
Request
   ↓
Authorization Filter
   ↓
Resource Filter ← Before
   ↓
Model Binding
   ↓
Action Filter
   ↓
Controller Action
   ↓
Result Filter
   ↓
Resource Filter ← After
   ↓
Response
```

### Key Points

* Runs **before model binding** and action execution.
* Can **short-circuit** the request.
* Useful for **caching, performance checks, and request preprocessing**.
* `IAsyncResourceFilter` is preferred when the operation involves asynchronous work.

**Interview point:** Resource filters run early in the pipeline, **before model binding**, making them suitable for scenarios where you want to avoid unnecessary processing.
