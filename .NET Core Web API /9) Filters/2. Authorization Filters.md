# Authorization Filters in ASP.NET Core Web API

**Authorization Filters** are used to determine **whether a user is allowed to access an API endpoint**.

They run **before other filters and before the controller action executes**.

### Key Points

* Used for **authorization/security checks**.
* Execute **first** in the filter pipeline.
* Can inspect the current user, claims, roles, etc.
* If authorization fails, the action is **not executed**.
* For most modern APIs, prefer **ASP.NET Core's built-in `[Authorize]` attribute and authorization policies** rather than writing custom authorization filters.

### Example

```csharp
[Authorize(Roles = "Admin")]
[HttpGet]
public IActionResult GetUsers()
{
    return Ok("Admin users only");
}
```

Only authenticated users with the **Admin role** can access this endpoint.

# Custom Authorization Filter in ASP.NET Core Web API

A **Custom Authorization Filter** allows you to implement your own authorization logic instead of relying only on `[Authorize]`.

It implements the `IAuthorizationFilter` interface and executes **before the controller action**.

### Example

```csharp
public class CustomAuthorizationFilter : IAuthorizationFilter
{
    public void OnAuthorization(AuthorizationFilterContext context)
    {
        var user = context.HttpContext.User;

        if (!user.Identity!.IsAuthenticated)
        {
            context.Result = new UnauthorizedResult();
            return;
        }

        if (!user.IsInRole("Admin"))
        {
            context.Result = new ForbidResult();
        }
    }
}
```

### Apply to Controller

```csharp
[ServiceFilter(typeof(CustomAuthorizationFilter))]
[ApiController]
public class UsersController : ControllerBase
{
    [HttpGet]
    public IActionResult GetUsers()
    {
        return Ok("Users data");
    }
}
```

Register the filter:

```csharp
builder.Services.AddScoped<CustomAuthorizationFilter>();
```

### Flow

```text
Request
   ↓
Custom Authorization Filter
   ↓
Authorized?
  /     \
 No      Yes
 ↓        ↓
401/403  Action executes
```

### `Unauthorized` vs `Forbid`

* **401 Unauthorized** → User is **not authenticated**.
* **403 Forbidden** → User is authenticated but **doesn't have permission**.

**Note:** For normal role/policy-based authorization, `[Authorize]` with policies is generally preferred. Custom authorization filters are useful when you have **special/custom authorization rules**.


### Authentication vs Authorization

| Authentication          | Authorization                   |
| ----------------------- | ------------------------------- |
| **Who are you?**        | **What are you allowed to do?** |
| Verifies identity       | Verifies permissions            |
| Example: JWT validation | Example: Admin role             |

**Interview point:** Authorization filters run **before the action**, and setting `context.Result` prevents the action from executing.
