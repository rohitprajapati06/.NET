# Exception Filters in ASP.NET Core Web API

**Exception Filters** are used to handle **unhandled exceptions** thrown during controller action execution.

They implement:

* `IExceptionFilter` → Synchronous
* `IAsyncExceptionFilter` → Asynchronous

### Example

```csharp
public class GlobalExceptionFilter : IExceptionFilter
{
    public void OnException(ExceptionContext context)
    {
        context.Result = new ObjectResult(new
        {
            Message = "Something went wrong"
        })
        {
            StatusCode = 500
        };

        context.ExceptionHandled = true;
    }
}
```

Register globally:

```csharp
builder.Services.AddControllers(options =>
{
    options.Filters.Add<GlobalExceptionFilter>();
});
```

### How It Works

```text
Request
   ↓
Controller Action
   ↓
Exception occurs
   ↓
Exception Filter
   ↓
Custom Error Response
   ↓
Client
```

### Key Points

* Handles **unhandled exceptions** from controller/action execution.
* Prevents exposing sensitive exception details to clients.
* Can return a **custom HTTP response** such as `500 Internal Server Error`.
* `context.ExceptionHandled = true` indicates that the exception has been handled.
* For modern ASP.NET Core APIs, **global exception-handling middleware / `IExceptionHandler`** is generally preferred for application-wide exception handling.

**Interview point:** Exception Filters are mainly intended for handling exceptions **within the MVC/controller pipeline**; middleware is better for handling exceptions across the entire application pipeline.
