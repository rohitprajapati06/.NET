# Filters in ASP.NET Core Web API

**Filters** in ASP.NET Core Web API allow you to execute custom logic **before or after specific stages of the HTTP request pipeline**.

They are commonly used for **authorization, validation, logging, exception handling, and modifying responses**.

### Filter Types

| Filter                   | Purpose                                       | Execution               |
| ------------------------ | --------------------------------------------- | ----------------------- |
| **Authorization Filter** | Checks whether the user is authorized         | First                   |
| **Resource Filter**      | Runs before/after resource execution          | Early in pipeline       |
| **Action Filter**        | Executes logic before/after controller action | Around action           |
| **Exception Filter**     | Handles exceptions from actions               | When exception occurs   |
| **Result Filter**        | Executes before/after action result           | Around result execution |


### Filter Execution Flow

```text
Request
   ↓
Authorization Filter
   ↓
Resource Filter
   ↓
Action Filter
   ↓
Controller Action
   ↓
Result Filter
   ↓
Response
```

**Key point:** Filters are useful when you want to apply **cross-cutting logic** to controllers/actions without repeating the same code in every action.
